<h2 id="what-it-is">它是什么</h2>

函数调用是工具调用的一种结构化接口：应用把可用函数的说明和参数 Schema 提供给模型，模型返回要调用的函数及参数。它让应用不必从自由文本里猜测执行意图，但模型返回的是调用请求，不是函数已经运行的证明。[S1][S2]

<h2 id="why-it-matters">为什么需要它</h2>

若模型只回复“请查询订单 123”，程序还要解析句子、判断字段并处理歧义；稍微改变措辞就可能失败。函数调用把意图收敛到已声明的函数和字段，使应用更容易验证、记录和测试，也能把函数结果与具体调用关联起来，再交给模型组织最终回答。[S1]

<h2 id="how-it-works">它如何工作</h2>

应用声明函数名、用途、参数类型与必填规则，并把它们随请求发送给模型。模型可能直接回答，也可能返回函数选择和参数；应用检查 Schema、业务规则、用户权限和副作用后执行函数，再把带调用标识的结果回传。模型随后解释结果或发起下一次调用。OpenAI 和 Anthropic 的字段名称不同，但“声明 -> 请求 -> 执行 -> 回传”是共同主干。[S1][S2]

<h2 id="confusions">必须澄清的误会</h2>

**函数调用 ≠ 工具调用。** 函数调用是「把工具请求表达成结构化数据」的格式约定；工具调用是完整能力，还包括工具清单、权限、结果校验与失败后的重新决策。

**函数调用 ≠ API 调用。** 函数调用发生在模型与应用之间，解决「模型想调什么」；API 调用发生在应用与外部系统之间，解决「怎么真的调通」。

<h2 id="example">真实例子</h2>

客服助手可以获得 `get_order(order_id)` 和 `request_refund(order_id, reason)` 两个函数。用户只问物流时，模型应调用查询函数；用户要求退款时，即使生成了格式正确的参数，应用仍要核验订单归属、退款期限和操作权限。未通过时返回业务错误，由助手解释原因，而不是因为 JSON 合法就创建退款。

<h2 id="tradeoffs">什么时候适合与不适合</h2>

函数调用适合连接边界清楚的 API、数据库查询和业务动作，也适合需要可靠字段而非自然语言的流程。纯文本创作不一定需要它。严格 Schema 能约束结构，却不能证明参数真实、业务允许或函数安全；函数描述含糊也会导致选错工具。应用仍需鉴权、限流、超时、错误处理和审计。[S1][S2]

<h2 id="try-it">亲自试一下</h2>

为“预约会议室”写一个函数契约，限定日期、开始时间、时长和人数。准备六个测试：正常预约、日期缺失、人数超限、用户无权限、时段冲突和重复提交。分别写出 Schema 校验、业务校验与执行层应处理的问题；只有三层责任没有混在一起，契约才算清楚。
