<h2 id="what-it-is">它是什么</h2>

多智能体系统是由多个具有不同角色或能力的 Agent 协作完成任务的系统，需要处理通信、冲突和总体控制。在Agent 与自动化里，它通常作为一个可复核的入口，用来把概念、对象和判断条件对齐。[S1][S2]

<h2 id="why-it-matters">为什么需要它</h2>

理解多智能体系统能帮助你判断问题是否真的落在这个概念上，而不是被相近名词带偏。它属于这个领域的基础入口，适合放在前面学习。最后连着系统取舍、成本和失败模式一起看。

<h2 id="how-it-works">它如何工作</h2>

它通常先确认输入、约束、流程和输出，再检查这些部分能否被复核。这样做可以把抽象名词落到具体判断上，也方便和其他词条做关系对照。

<h2 id="confusions">必须澄清的误会</h2>

**多智能体系统 ≠ Agent 编排。** 多智能体系统是架构选择，Agent 编排是让它跑起来的调度逻辑，前者决定有多少角色后者决定怎么配合。
**多智能体系统 ≠ AI Agent。** AI Agent 通常指单个能调用工具的执行体，多智能体系统由多个这样的执行体组成。

<h2 id="example">真实例子</h2>

例如，在一个真实的Agent 与自动化场景中，团队会先把多智能体系统放进当前问题里，再决定要不要继续拆成数据、流程、接口或评估步骤。Building Effective Agents 和 Trustworthy Agents in Practice 会是很好的核验起点。

<h2 id="tradeoffs">什么时候适合与不适合</h2>

它适合被用来统一语言、减少歧义和梳理边界，但不适合被当成万能解释。若定义太粗，容易掩盖条件差异；若过早套用，也会把本来简单的问题说复杂。

<h2 id="try-it">亲自试一下</h2>

拿一件你正在处理的事试一次：用约 40 分钟，把一件可以并行的事拆给两个角色（一个写、一个查），与单 Agent 一次做完的结果比较差异在哪。
