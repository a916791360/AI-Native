<h2 id="what-it-is">它是什么</h2>

浏览器操作是 AI 在浏览器中导航页面、读取状态并执行交互操作的工具使用场景。在Agent 与自动化里，它通常作为一个可复核的入口，用来把概念、对象和判断条件对齐。[S1][S2]

<h2 id="why-it-matters">为什么需要它</h2>

理解浏览器操作能帮助你判断问题是否真的落在这个概念上，而不是被相近名词带偏。它属于这个领域的基础入口，适合放在前面学习。再把机制、前提和依赖关系补齐。

<h2 id="how-it-works">它如何工作</h2>

它通常先确认输入、约束、流程和输出，再检查这些部分能否被复核。这样做可以把抽象名词落到具体判断上，也方便和其他词条做关系对照。

<h2 id="confusions">必须澄清的误会</h2>

**浏览器操作 ≠ 计算机操作。** 浏览器操作只限于网页之内，计算机操作作用于整个桌面，包括本地软件与文件管理器。
**浏览器操作 ≠ API 调用。** 接口调用稳定且结构化，浏览器操作靠识别界面元素，后者是接口缺失时的兜底手段。

<h2 id="example">真实例子</h2>

例如，在一个真实的Agent 与自动化场景中，团队会先把浏览器操作放进当前问题里，再决定要不要继续拆成数据、流程、接口或评估步骤。Building Effective Agents 和 Trustworthy Agents in Practice 会是很好的核验起点。

<h2 id="tradeoffs">什么时候适合与不适合</h2>

它适合被用来统一语言、减少歧义和梳理边界，但不适合被当成万能解释。若定义太粗，容易掩盖条件差异；若过早套用，也会把本来简单的问题说复杂。
