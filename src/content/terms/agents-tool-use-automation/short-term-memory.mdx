<h2 id="what-it-is">它是什么</h2>

短期记忆是在当前任务或会话范围内保存临时信息的记忆形式，通常随任务结束而清理。在Agent、工具调用与自动化中，短期记忆主要用于保存当前任务进行到哪一步，让 Agent 在多轮工具调用之间不丢上下文。[S1][S2]

<h2 id="why-it-matters">为什么需要它</h2>

掌握短期记忆的核心价值在于明确其适用范围与设计目标。如果脱离具体业务约束，不跨任务，会话结束就清空，下一次进来仍然是白纸一张。作为Agent、工具调用与自动化的核心概念，透彻掌握短期记忆有助于推导整个系统的设计基准。

<h2 id="how-it-works">它如何工作</h2>

在系统运转过程中，短期记忆的实现重点在于输入约束、中间处理与输出验证的闭环。具体到工程落地，围绕「保存当前任务进行到哪一步，让 Agent 在多轮工具调用之间不丢上下文」这一核心任务，短期记忆在运行时会针对输入与约束进行动态校验，并通过标准处理链路达成预期状态。通过将抽象目标拆解为可复核的步骤，短期记忆能够稳定支撑上层应用的业务逻辑。

<h2 id="confusions">必须澄清的误会</h2>

**短期记忆 ≠ 长期记忆。** 短期记忆只在本次会话内有效，长期记忆跨会话保留，前者管进度后者管积累。
**短期记忆 ≠ 上下文窗口。** 上下文窗口是模型能一次读入的容量上限，短期记忆是这份容量里被有意维护的那部分状态。

<h2 id="example">真实例子</h2>

例如在推进Agent、工具调用与自动化相关的实际工程中，团队若要达成保存当前任务进行到哪一步，让 Agent 在多轮工具调用之间不丢上下文。，往往会以短期记忆作为关键控制点或评价标准。深入研读 Building Effective Agents 和 Trustworthy Agents in Practice 中给出的案例与方案，能够清晰还原短期记忆在端到端链路里的输入输出约束与实际运转效果。

<h2 id="tradeoffs">什么时候适合与不适合</h2>

**适合的场景**：当系统面临明确的需求，且目标集中在保存当前任务进行到哪一步，让 Agent 在多轮工具调用之间不丢上下文时，引入短期记忆能提供坚实的方法论支撑与执行标准。

**不适合的场景**：如果面临超出边界的挑战，尤其是不跨任务，会话结束就清空，下一次进来仍然是白纸一张，切忌将短期记忆作为兜底方案，否则容易引发过度设计或隐藏系统瓶颈。
