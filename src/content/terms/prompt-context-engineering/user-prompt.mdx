<h2 id="what-it-is">它是什么</h2>

用户提示词是终端用户在当前交互中提交的任务、问题、材料和约束。它可以只是一句提问，也可以包含待处理文本、目标读者、结果格式与判断标准。在角色化对话协议中，这类输入通常作为用户消息进入模型上下文。[S1][S2]

<h2 id="why-it-matters">为什么需要它</h2>

用户提示词连接真实需求与模型能力。只写“分析一下”会遗漏对象、目的和完成标准；说明“为产品周会比较三条投诉的共同原因，并标出证据不足处”后，输出才更容易被检查。好的输入不是追求神秘措辞，而是让任务、材料和边界可见。

<h2 id="how-it-works">它如何工作</h2>

应用把用户输入组织成包含角色和内容的消息，并与系统指令、对话历史、工具结果等一起提交。Anthropic Messages API 使用 `role` 与 `content` 表示用户和助手轮次；OpenAI Model Spec 则说明用户指令处于更高层规则之下。[S1][S2] 这些内容在推理时影响本次生成，正常情况下不会因为一次消息就更新模型参数。

<h2 id="confusions">必须澄清的误会</h2>

**用户提示词 ≠ 提示词。** 提示词是模型收到的全部输入的总称（含系统提示、示例、资料）；用户提示词特指用户自己写的那部分。

**用户提示词 ≠ 系统提示词。** 系统提示词由开发者写、优先级更高且用户看不见；用户提示词由使用者写、每次不同。两者冲突时怎么取舍由指令层级决定。

<h2 id="example">真实例子</h2>

产品经理可以提交：“根据以下五条访谈记录，为下周评审整理三个用户问题；每个问题附原话证据，不推断未提及的人口属性；若证据不足写‘待验证’；输出表格。”这里同时交代了输入材料、使用目的、禁止推断项和结果格式，评审者可以逐项核对。

<h2 id="tradeoffs">什么时候适合与不适合</h2>

用户提示词适合表达当轮目标、提供材料并说明验收方式，但不能获得应用没有授予的权限，也不能让缺失事实凭空出现。粘贴网页、邮件或文档时，其中的文字可能只是数据，也可能夹带与任务冲突的指令；应用需要区分可信规则和待处理内容，而不是把所有文本都当命令。[S1]

<h2 id="try-it">亲自试一下</h2>

找一个真实任务，按“目标、输入、约束、格式、成功标准”五栏重写用户提示词。删除其中任意一栏并比较结果，记录哪类缺失最影响判断。若结果仍无法验收，继续补充可观察标准，而不是只添加“认真”“专业”等抽象形容词。
