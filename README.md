# AI-Native

> 面向落地实践的 AI 产品经理与从业者系统化学习平台。拒绝空洞概念泛滥，从**单点决策判断**、**连续实战案例**、**认知主干链路**到**严谨知识参考**，建立端到端的 AI 商业落地与工程决策能力闭环。

**当前版本：v0.13.0**（2026-09-28）——全量实战案例深度核验（Verified）：晋升除客服外的其余 5 大实战案例（用户反馈分析、销售跟进助手、合同条款审核助手、内容生产助手、内部运营自动化）至 Verified 状态，补齐研究包、逐项来源核验与 Gate 证据契约，案例库 6 大案例全量核验闭环。阶段 0-10 已完成（技术基线）；学习体系 V2 阶段 11-14 已完成。

---

## 为什么需要 AI-Native？

市面上现有的 AI 教程与资料大多处于两个极端：

- **概念泛滥 / 新闻搬运**：充斥着「大模型重塑一切」的宏大叙事，但在面对具体业务时，无法判断场景是否真的需要 AI；
- **纯代码 / API 套壳**：停留于调用 `openai.ChatCompletion.create()` 的简易接口，对真实上线中的**准确率陷阱、幻觉容错、工程边界、单位经济模型（Unit Economics）与成本失控**闭口不谈。

**AI-Native 的核心主张**：

> 「学 AI 产品，不是背诵术语，而是掌握在不确定性中做确定性工程决策的能力。」

通过**认知主干、阶梯题库、实战决策台与图谱网络**四维联动，帮助你建立能够落地的 AI 产品思维：

1. **判断是否需要 AI**：识别强规则、检索增强还是大模型生成，拒绝「为了 AI 而 AI」；
2. **拆解落地工程**：定义明确的人机协作分工、输入/输出契约与上下文工程；
3. **处理失败与容错**：在幻觉与不可控性出现时，设计优雅的兜底降级与审查回路；
4. **算清商业成本账**：测算 Token 消耗、吞吐延迟、算力账本与 ROI 投入产出比。

## 四大核心学习体系

### 1. 认知主干链路（`/map/`）

- **8 站递进式主干**：从「第 1 站：输入与 Prompt」贯穿至「第 8 站：业务衡量」，构建逻辑严密、不迷茫的学习骨架；
- **高频概念全景导览**：覆盖 22 个常见概念，清晰标注「它在解决什么问题」、「常见困惑」与「对应架构层级」；
- **沉浸式交互体验**：桌面与移动端平滑吸顶 Tab 导引，触控单行横向滑轨与活跃站点自动居中，一键锚点穿透跳转。

### 2. 三层进阶判断题库（`/learn/`）

- **三层深度梯度（共 90 题）**：
  - **Tier 1 概念识别**：基础特征与适用边界甄别（3 选项）；
  - **Tier 2 场景判断**：真实工程条件匹配与权衡（3–4 选项，含「有条件成立」项）；
  - **Tier 3 深度权衡**：复杂业务风险、合规与成本博弈（4 选项，深度多维权衡）；
- **PM 落地动作指引**：每道题均配备真实的业务踩坑经验与落地执行清单；
- **六维能力雷达（Competency Radar）**：纯 SVG 矢量能力图谱，根据答题情况动态测算「模型边界、场景机会、方案选型、体验交互、评测约束、综合实战」六维得分与段位评级（L1 Observer → L5 Principal），精准推荐薄弱攻坚项。

### 3. 六大业务实战案例库（`/learn/cases/`）

已全量晋升为 **Verified（深度来源核验）** 的 6 大典型工业级场景，每个案例包含 6 个递进评审关卡（共 36 个 Gate 决策台）：

- **客户支持智能知识库**（Customer Support KB）：RAG 检索增强、检索精度与幻觉拦截；
- **销售跟进与线索转化助手**（Sales Copilot）：非结构化对话提取、意图识别与推荐跟进；
- **法务合同条款审核助手**（Contract Review）：高敏感场景、严格证据留痕与人类复核；
- **营销内容批量生产助手**（Content Generation）：品牌一致性、提示链工程与质量打分；
- **企业内部运营自动化**（Internal Operations）：Tool Calling、复杂工具调用与权限隔离；
- **每日用户反馈分析与改进**（User Feedback Analysis）：情绪聚类、优先级打分与产品需求沉淀。

每个 Gate 均包含**业务上下文、事实与假设清单、已知/未知项边界、决策选项权衡、证据材料沉淀与失败恢复设计**。

### 4. 严谨知识库与语义图谱（`/atlas/` & `/graph/`）

- **325 个规范词条**：涵盖 13 大知识领域（含独创的「AI 产品经理基本功」领域）；
- **全站 0% 模板套话**：所有词条均深度绑定真实解决边界（Solves / Not Solves）与上手动作，无空洞生成废话；
- **真实双向语义边**：严格人工审定的前置（Prerequisite）、组成（Component）、比较（Comparison）、应用（Application）关联；
- **离线端高性能检索**：集成 Pagefind 静态全文检索引擎，毫秒级即时响应，零外部服务依赖。

## 视觉与交互规范（Better-Interface & Transitions Engine）

本项目严格遵循高质量现代 Web 设计标准与无障碍规范：

- **Daylight Clean 晨光高质感门户**：清爽象牙白底（`#F8FAFC`）、纯白高层悬浮卡片、深板岩高对比墨水字（`#0F172A`）与皇家科技蓝（`#2563EB`）功能强调；
- **字重对比契约（No Middle Weights）**：设计系统严格只使用 400（常规体）与 800（粗黑体）两级极端字重，杜绝 500/600 造成的视觉灰度混淆，字重落差 >= 300；
- **Transitions.dev 动效规范**：系统化定义持续时间（40ms/80ms/150ms/250ms/350ms）与微交互回弹曲线（`cubic-bezier`），按压即带微触觉反馈（Active Scale），开启 `prefers-reduced-motion` 立即无缝降级；
- **智能双层吸顶与锚点对齐**：顶栏（4rem）与页面导引条紧密配合，全局注入 `scroll-padding-top` 与自适应 `scroll-margin`，彻底消除锚点跳转被顶栏遮盖的体验顽疾。

## 本地开发指南

### 环境要求

- **Node.js**：`>= 22 < 25`（推荐 Node.js 24 LTS）
- **包管理器**：`pnpm 11.9.0`（通过 Corepack 或独立安装）

### 常用命令

```bash
# 1. 冻结依赖安装
pnpm install --frozen-lockfile

# 2. 启动本地开发服务 (http://localhost:4321)
pnpm dev

# 3. 内容校验与管线生成
pnpm validate:data   # 校验词条、目录与生产状态
pnpm generate:data   # 依据事实源重新构建注册表与图谱数据

# 4. 执行全套测试套件
pnpm test:unit       # 运行 223 个 Vitest 单元与契约测试
pnpm test:e2e        # 运行 Playwright 浏览器端到端测试

# 5. 生产构建与检索索引构建
pnpm build

# 6. 本地全量 CI 门禁检查 (与 GitHub Actions 一致)
pnpm run ci
```
