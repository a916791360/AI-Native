# AI-Native 产品与技术设计规格

- 状态：已于 2026-07-29 完成书面复核，批准进入实施计划约定的开发阶段
- 日期：2026-07-29
- 产品名称：AI-Native
- 产品类型：面向中文 AI 初学者与产品人的渐进式 AI 知识图鉴
- 参考产品：VibeHub 的搜索、分类、可视化词条和概念连接机制
- 独立性原则：借鉴信息机制，不复制 VibeHub 的品牌、文案、页面结构或视觉外观

## 1. 产品定义

AI-Native 是一套由浅入深的中文 AI 知识体系。它不是只解释几个热门工具，也不是把专业名词堆成字典，而是让用户沿着“查到一个概念—听懂它—看懂它与其他概念的关系—判断何时使用—继续进入学习路线”的路径，逐步建立能够用于真实工作的 AI 认知。

产品的核心承诺是：

> 帮助用户从“听说过 AI”进阶到“能理解核心概念、判断业务场景是否适合 AI，并设计一个基础 AI 解决方案”。

## 2. 目标用户与核心任务

### 2.1 主要用户

- 第一次系统学习 AI 的中文初学者。
- 在工作中使用过 AI 工具，但不了解 RAG、向量、Agent、评估等底层概念的职场人。
- 需要判断 AI 产品机会、与研发沟通或撰写方案的产品经理、运营、设计师和创业者。
- 希望补齐概念体系、快速查证术语关系的非算法技术人员。

### 2.2 用户要完成的任务

- 听到一个陌生 AI 术语时，能快速查到并用通俗语言理解。
- 识别术语的英文原名、常见缩写、别名和容易混淆的概念。
- 理解一个概念为什么出现、如何工作、解决什么问题及其局限。
- 看见概念的前置知识、组成部分、对比对象和实际应用。
- 从零散查词进入一条有顺序的学习路线。
- 最终把概念用于业务判断、产品设计或简单实验。

## 3. 产品目标与非目标

### 3.1 产品目标

- 建立覆盖应用 AI 核心知识，并可向算法、训练和算力扩展的完整词条目录。
- 同时提供高效索引、渐进式课程和概念关系图三种入口。
- 建立可公开检查的来源、核验、修订和纠错机制。
- 通过结构化内容和自动校验，让词条数量增长时仍保持一致性。
- 首版无需账号、后端或内容管理系统即可快速、稳定地访问。

### 3.2 首版明确不做

- 用户注册、登录、云端收藏和学习进度同步。
- 评论、社区、投稿审核和复杂内容后台。
- AI 对话助手或基于站内内容的问答机器人。
- 新闻资讯流、模型排行榜和实时生态数据。
- 付费、订阅和商业化系统。
- 强制编程练习或完整在线编程环境。

上述能力可作为未来独立项目评估，但不属于首版设计和实现范围。

## 4. 知识范围

知识体系采用“两圈模型”：

1. 应用 AI 核心圈：所有目标用户都需要理解的概念，优先完成。
2. 算法、训练与算力扩展圈：为希望深入的用户提供继续学习入口，不要求初学者从这里开始。

词条按十二个知识领域组织：

1. AI 基础与发展史
2. 机器学习与深度学习
3. 大语言模型与生成式 AI
4. 提示词与上下文工程
5. 多模态
6. 数据、检索与 RAG
7. Agent、工具调用与自动化
8. AI 产品与用户体验
9. 评估、可观测性与质量
10. AI 工程、部署与运维
11. 安全、伦理与治理
12. 算力、芯片与产业生态

模型与行业动态采用“稳定知识核心 + 动态生态观察”的长期结构。首版只实现稳定知识核心，并在数据结构和导航中为动态内容保留扩展位置，不上线资讯频道。

## 5. 内容交付范围

### 5.1 第一阶段：可上线版

- 建立约 300–500 个词条的完整目录。
- 所有目录词条具备中英文名称、别名、领域、难度、内容状态和关系信息，并可被搜索和浏览。
- 首批 80–120 个核心词条完成统一深度模板、来源核验和正式发布。
- 其余词条明确标为“已收录，待完善”，不得伪装成已完成内容。
- 完成四条首发学习路线及路线所需的核心内容。
- 完成首页、知识图鉴、学习路线、词条详情、概念图谱、内容方法六类页面。

### 5.2 第二阶段：完整内容版

- 将目录内剩余词条逐步全部提升到深度词条标准。
- 清除只含一句定义的占位词条；保留状态只用于真实的修订或复核过程。
- 补齐跨领域关系、应用案例、可视化解释和可操作练习。
- 完成全部词条的来源、核验日期与修订记录。

第一阶段上线不是项目结束。完整内容版属于 AI-Native 的整体交付目标，但通过分阶段方式保证用户能更早使用真实、可靠的核心内容。

## 6. 信息架构

### 6.1 全局导航

- 首页
- 知识图鉴
- 学习路线
- 概念图谱
- 内容方法
- 全局搜索入口

### 6.2 首页

首页承担品牌解释和学习分流，不展示一个缺少上下文的巨大节点球。

主要区块：

1. AI-Native 的一句话价值说明。
2. 全局搜索：支持中文、英文、缩写和别名。
3. “从哪里开始”入口：四条首发路线。
4. 十二个知识领域的关系场概览。
5. 推荐核心词条与近期完成内容。
6. 内容规模、已核验数量和方法说明。

### 6.3 知识图鉴

知识图鉴是高效率索引台，默认以列表或卡片索引为主，而不是用图谱替代浏览。

支持：

- 关键词搜索。
- 按领域、难度、内容状态筛选。
- 按中文名、英文名或推荐顺序排序。
- 清楚区分“已核验”和“待完善”。
- 无结果时展示拼写建议、相关概念和领域入口。

### 6.4 学习路线

首发四条路线：

1. AI 零基础入门
2. 高效人机协作
3. AI 产品与场景判断
4. RAG 从零到理解与应用

每条路线包含适合人群、学习目标、预计知识量、章节顺序、前置知识和学完后的能力。无账号情况下不记录个人进度，不制造虚假的百分比进度。

### 6.5 词条详情

每个深度词条使用统一结构：

1. 它是什么
2. 为什么需要它
3. 它如何工作
4. 真实例子
5. 什么时候适合使用、什么时候不适合以及代价
6. 亲自试一下
7. 接下来学什么
8. 来源、核验信息和修订记录

“亲自试一下”可采用提示词实验、判断题、交互演示或场景练习，不强制写代码。

### 6.6 概念图谱

概念图谱用于探索关系，不承担唯一导航职责。

- 桌面端支持平移、缩放、节点选择、领域和关系类型筛选。
- 移动端默认展示当前概念的局部关系或关系列表，避免强行塞入完整大图。
- 选择节点后显示通俗摘要、关系解释和词条入口。
- 图谱不可用时退化为结构化关系列表。

### 6.7 内容方法页

公开说明内容范围、来源优先级、核验标准、状态含义、修订方式和纠错入口。纠错入口首版使用 GitHub Issues，不建设自有反馈后台。

## 7. 视觉与交互方向

视觉系统采用已经确认的混合方向：

- 首页和品牌识别使用 C“关系场”：表达概念不是孤岛，形成独立品牌记忆。
- 知识图鉴和全局搜索使用 A“索引台”：强调查找效率、结构密度和清楚状态。
- 学习路线和长篇阅读使用 B“学习刊物”：强调中文阅读节奏、章节秩序和由浅入深。
- 词条详情融合三者：刊物式正文、局部关系图和高效索引信息。

设计约束：

- 仅使用“AI-Native”文字标识，Logo、品牌色和正式字体尚未定义，不得自行虚构最终品牌资产。
- 避免通用紫色渐变、霓虹科技模板、装饰性图标、虚构数据和堆叠式 Bento 卡片。
- 视觉化必须服务概念解释；找不到合适图形时使用清晰文字，不使用装饰性占位图。
- 参考文件位于 `docs/product/design-demos/`，方向记录位于 `docs/product/direction-approved.md`。

## 8. 搜索设计

搜索采用双层机制：

1. 轻量词条注册表负责中文名、英文名、缩写和别名的精确与前缀命中。
2. 静态全文索引负责正文搜索、相关结果和筛选。

结果排序规则：

1. 中文名或英文名完全一致。
2. 缩写或别名完全一致。
3. 标题前缀匹配。
4. 标题模糊匹配。
5. 正文相关结果。
6. 关联概念和学习路线建议。

筛选维度为领域、难度和内容状态。搜索必须支持简体中文正文、英文原名和双语别名。首版不承诺智能语义搜索，避免为数百词条过早引入向量数据库和后端服务。

## 9. 概念关系模型

图谱边限定为四类，每条关系都必须带有简短解释：

- 前置：理解目标概念前应先理解什么。
- 组成：一个概念由哪些部分构成或属于哪个更大结构。
- 比较：两个容易混淆或存在替代关系的概念。
- 应用：概念被用于什么方法、产品或业务场景。

关系数据独立于词条正文保存，以避免双向关系重复维护。构建阶段生成反向关系和局部图数据。

自动检查包括：

- 关系引用的词条是否存在。
- 是否存在无合理解释的自连接。
- 是否存在异常前置循环。
- 已发布核心词条是否成为孤立节点。
- 重复关系和冲突关系是否需要人工复核。

## 10. 内容数据模型

### 10.1 词条元数据

每个词条至少包含：

- 唯一标识和稳定 URL。
- 中文名称、英文原名、缩写和别名。
- 一句话解释。
- 所属领域和难度。
- 内容状态。
- 是否属于应用核心圈。
- 首次发布日期、最近更新日期和最近核验日期。
- 来源清单。
- 正文内容。

### 10.2 学习路线数据

每条路线包含：

- 路线名称与稳定标识。
- 适合人群、前置知识和学习目标。
- 有序章节与词条引用。
- 章节之间的过渡说明。
- 路线完成后的能力描述。

### 10.3 内容状态

- `catalogued`：已收录，仅具备目录元数据。
- `draft`：正文正在编写，不公开或明确标注草稿。
- `verified`：通过来源和质量校验，可正式发布。
- `needs-review`：来源失效、内容过期或存在争议，需要复核。
- `deprecated`：术语已过时或被替代，保留历史说明与跳转。

状态必须出现在页面和搜索结果中，不能只存在于内部数据里。

## 11. 内容权威与生产流程

AI-Native 不宣称任何内容绝对无误，而是对可追溯、可复核和及时修正负责。

### 11.1 来源优先级

1. 原始研究论文、标准、法律法规和技术规范。
2. 官方产品、模型、框架和机构文档。
3. 权威教材、大学课程或研究机构资料。
4. 高质量工程实践资料，用于补充实际经验。
5. 媒体或个人文章仅作为线索或观点，不用于单独支撑关键事实。

涉及定义、机制、数字、能力边界和风险的关键主张原则上进行双来源核对。无法找到第二个独立可靠来源时，必须说明证据限制，不把推断写成事实。

### 11.2 生产流程

1. 建立完整词条目录。
2. 按基础性、使用频率、路线依赖和业务价值确定优先级。
3. 为词条制作研究包，收集原始来源和关键事实。
4. 按统一模板起草内容。
5. 执行事实、术语、案例、观点和可视化一致性检查。
6. 标记核验日期和内容状态后发布。
7. 通过 Git 历史、页面修订记录和 GitHub Issues 持续纠错。

### 11.3 写作质量规则

- 首次出现的专业词必须解释或链接到前置词条。
- 不允许用另一个更难懂的术语完成循环解释。
- 明确区分事实、行业共识、实践建议和作者解释。
- 示例必须说明适用条件，不能把单一经验包装成普遍规律。
- 可视化、正文和关系数据表达的机制必须一致。
- 快速变化的信息必须注明验证日期、版本或时间边界。

## 12. 技术架构

首版采用内容优先的静态架构，不引入数据库、身份系统或运行时内容服务。

推荐技术组合：

- Astro：静态页面生成和整体应用结构。
- MDX 与 Astro Content Collections：词条正文、路线和结构化内容管理。
- 结构化 JSON、YAML 或 TypeScript 数据：关系边、领域和搜索别名注册表。
- Pagefind：构建后的静态全文搜索、中文分词和筛选。
- Cytoscape.js：桌面端及局部概念图谱交互。
- GitHub Actions：自动校验、测试、构建和后续部署。

选择理由：

- 内容在仓库内可版本追踪和批量审查。
- 静态输出速度快、成本低，适合数百到上千个词条。
- 搜索和图谱只在需要时加载，不让整站变成重型单页应用。
- 以后可接入 CMS、动态栏目或后端，而无需重写词条数据模型。

部署产物保持平台无关。首选 GitHub Pages，但在用户明确要求部署前不绑定或执行发布。

- Cytoscape.js：<https://js.cytoscape.org/>

## 13. 构建与数据流

1. 作者在仓库中新增或修改词条、关系、领域或路线文件。
2. 内容模式校验字段、枚举、日期、引用和唯一标识。
3. 关系校验器检查断链、孤立节点、循环、重复和冲突。
4. Astro 生成静态词条页、索引页、路线页和方法页。
5. 构建过程生成轻量词条注册表和图谱数据。
6. Pagefind 扫描静态页面并生成全文搜索索引。
7. 自动测试检查链接、搜索、关键页面、移动端布局和无障碍要求。
8. 所有检查通过后才允许生成可发布产物。

运行时没有中心数据库请求。浏览器直接读取静态页面；用户打开搜索时加载搜索索引，进入图谱时加载图谱组件和所需的图数据。

## 14. 异常处理与降级

- 图谱脚本或布局失败：展示当前词条的结构化关系列表和相关词条链接。
- 搜索索引未加载：保留十二领域入口和按字母、中文拼音或推荐顺序浏览入口。
- 搜索无结果：展示清空筛选、别名建议、相近概念和反馈入口。
- 来源链接失效：词条自动或人工标记为 `needs-review`，保留已引用信息并提示待复核。
- 词条未完成：显示 `catalogued` 或 `draft` 状态以及相关已完成内容，不生成伪完整正文。
- 词条过时：标记 `deprecated`，解释替代概念并保留历史 URL。
- URL 不存在：404 页面提供全局搜索、热门领域和首页入口。
- 可视化示例不可用：始终保留等价的文字解释和关键数据。

## 15. 响应式与可访问性

- 桌面端优先保证索引效率和图谱探索空间。
- 移动端将多栏索引变成单栏筛选，将完整图谱变成局部图或关系列表。
- 所有核心操作可通过键盘完成。
- 颜色不是表达状态或关系类型的唯一方式，同时使用标签和文字。
- 页面保持正确标题层级、焦点顺序、足够对比度和清晰触控区域。
- 图像与可视化提供替代文字或等价文字解释。
- 尊重用户的减少动画偏好。

## 16. 测试策略

### 16.1 内容与模式测试

- 必填字段、状态、日期、来源格式和稳定标识。
- 中英文名、缩写和别名的重复或冲突。
- 已核验词条是否满足模板和来源要求。
- 内部词条链接、路线引用和来源链接。

### 16.2 搜索测试

- 中文名、英文原名、大小写不同的缩写和常用别名。
- 精确结果是否排在正文结果之前。
- 领域、难度和状态筛选的组合。
- 无结果、索引失败和慢速加载状态。

### 16.3 图谱测试

- 四类关系的显示、筛选和解释。
- 节点选择、平移、缩放、重置和词条跳转。
- 断链、孤立节点、前置循环和重复关系检查。
- 图谱失败后的关系列表降级。

### 16.4 页面与体验测试

- 首页、图鉴、路线、词条、图谱、方法页和 404 页面。
- 典型桌面、平板和手机视口。
- 键盘导航、焦点、颜色对比、语义结构和替代文本。
- 首屏、搜索索引和图谱的加载体积与交互流畅度。

## 17. 第一阶段验收标准

- 300–500 个目录词条均可搜索、筛选、浏览并出现在正确领域和关系数据中。
- 80–120 个核心词条达到统一深度模板且状态为 `verified`。
- 四条首发路线没有空章节，引用的核心内容可完整学习。
- 六类页面均可访问，并具备正常、空、错误和降级状态。
- 中文、英文、缩写和别名搜索通过固定测试样本。
- 图谱不存在无效引用；核心已发布词条没有非预期孤立节点。
- 桌面和移动端的关键任务均可完成。
- 内容方法、来源、核验日期、状态和修订入口对用户可见。
- 自动校验、测试和生产构建全部通过。

## 18. 成功判断

首版不依赖账号数据，优先使用任务型验证：

- 初学者能否在短时间内查到并复述一个陌生术语。
- 用户能否从一个词条找到必要前置知识和下一步内容。
- 用户能否完成一条路线并解释一个基础 AI 方案的组成和限制。
- 产品人员能否根据内容判断某个业务问题是否适合使用 RAG、Agent 或常规自动化。
- 用户能否看见关键结论的来源、时间边界和内容状态。

后续若接入匿名统计，应遵循最小化原则，只观察搜索无结果、页面使用和路线流转，不建立不必要的个人画像。

## 19. 仓库与后续工作边界

- 当前本地 Git 仓库是 AI-Native 后续开发和内容生产的唯一事实源。
- 本规格获书面确认后，下一步只编写实施计划，不直接跳入开发。
- 实施计划需要拆分为项目骨架、内容模式、页面系统、搜索、图谱、质量管线和首批内容等可验证阶段。
- 推送 GitHub、部署和公开域名均在用户明确授权后执行。
- 任何超出本规格的账号、社区、AI 问答或动态资讯能力，都需要单独设计与批准。

## 20. 已确认决策摘要

- 名称为 AI-Native。
- 服务中文初学者与产品型用户。
- 目标是“理解术语 + 判断与设计基础 AI 应用”。
- 产品由完整图鉴、学习路线和关系图谱共同构成。
- 内容采用应用核心圈与深层扩展圈。
- 首版建立 300–500 词目录，完成 80–120 个深度核验词条。
- 首发四类内容锚点和四条学习路线。
- 简体中文正文，保留英文原名与双语别名搜索。
- 不提供账号和学习进度存储。
- 首页采用关系场，图鉴采用索引台，路线采用学习刊物。
- 首版采用静态内容架构，不引入后端和向量数据库。
- 内容必须可追溯、可复核、可修订，不能以“绝对权威”代替证据流程。
- 整体目标包含最终深化全部目录词条，不在首批 80–120 个完成后停止。
