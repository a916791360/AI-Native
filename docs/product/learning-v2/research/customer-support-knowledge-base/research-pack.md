## 1. 研究结论

这个案例不应被定义为“给客服接入一个会回答问题的聊天机器人”，而应被定义为：

> 在知识版本、访问权限和原文证据可核验的前提下，为客服坐席提供回答草稿；检索不足、引用不支持、知识冲突或问题影响较高时拒绝自动作答并转交人工。

推荐方案是受限的检索增强工作流，而不是让模型直接读取全部资料并向客户自动回复：

1. 内容系统负责文档所有者、版本、生效时间、权限和下架状态。
2. 检索层负责在当前坐席和客户有权访问的有效知识中召回与重排。
3. 生成层只根据返回片段形成草稿，并把关键主张关联到真实原文。
4. 应用层校验引用、拒答、高风险路由、预算、日志和人工升级。
5. 客服坐席在早期阶段拥有修改、驳回、补充上下文和最终发送权限。

## 3. 范围 Gate

### 3.1 教学场景

`E1 案例设定`：某数字产品客服团队维护帮助中心、产品政策、故障处置手册和内部操作说明。坐席需要根据客户问题、账户状态和当前有效知识形成答复；退款承诺、账户限制、安全事件等问题必须按权限升级。

首版只辅助内部坐席，不直接面向客户自动回复，不执行退款、改价、封禁、删除或外发动作。

### 3.2 目标角色与责任

| 角色         | 责任                                           | 不下放给模型的决定       |
| ------------ | ---------------------------------------------- | ------------------------ |
| 客服坐席     | 确认问题语境、检查引用、修改或发送回答         | 是否向客户发送与是否升级 |
| 知识负责人   | 维护文档所有者、版本、生效日期、权限和下架状态 | 哪份政策当前有效         |
| 客服主管     | 定义高风险主题、升级路径和人工容量             | 例外处理、承诺与责任分配 |
| 产品与工程   | 维护检索、模型、日志、评测、降级和回滚         | 是否晋级、冻结或回滚版本 |
| 安全与合规方 | 审核敏感数据、权限、保留和事件响应             | 高影响权限与合规边界     |

### 3.3 目标与非目标

`R 产品建议`：目标是提高“有充分证据且经授权坐席确认的回答”完成效率，同时不提高无依据回答、错误版本引用和越权信息暴露。

本案例不承诺：

- 自动回答所有问题。
- 仅靠 RAG 消除模型编造、引用错误或提示注入。
- 以回答流畅度、点赞率或低转人工率单独证明成功。
- 用长上下文替代检索、版本治理和权限过滤。
- 在没有真实坐席确认与错误成本证据时开放自动外发。

## 4. 当前流程与关键未知项

### 4.1 教学用当前流程

```text
接收客户问题
  -> 识别客户、产品与问题类型
  -> 搜索帮助中心、政策与内部手册
  -> 检查版本、生效时间和适用条件
  -> 起草回答
  -> 高风险或无答案问题升级
  -> 发送并记录结果
```

该流程是 `E1 案例设定`，不证明真实团队使用同样工具或一定存在效率问题。

### 4.2 进入初稿前已固定的边界

- 知识文档先治理再索引；缺少所有者、版本或权限的文档不得进入可回答集。
- 权限过滤必须在检索和业务系统层执行，不能依赖提示词保密。
- 每个关键回答主张需要真实存在且支持该主张的原文引用。
- “检索到片段”不等于“片段支持答案”，检索与生成分开评测。
- 无答案、知识冲突、高风险或引用不支持时，默认拒答或升级人工。
- 检索内容视为不可信数据，不能取得系统指令或工具权限。

### 4.3 真实试点必须补齐的未知项

| 未知项                     | 为什么影响方案                   | 最小取证方式                       |
| -------------------------- | -------------------------------- | ---------------------------------- |
| 文档清单、所有者与版本历史 | 决定可回答范围和过期知识风险     | 盘点来源、权限、生效与下架字段     |
| 问题分布与无答案比例       | 决定检索、拒答和升级设计         | 对脱敏历史工单分层抽样             |
| 当前查找与回答耗时         | 决定是否存在值得解决的机会       | 区分搜索、阅读、起草、等待和返工   |
| 高风险问题与错误成本       | 决定召回、人工确认和自动化上限   | 与主管、安全和业务责任人共同定义   |
| 坐席权限与客户权限         | 决定检索过滤和可展示字段         | 建立角色、租户、客户和文档权限矩阵 |
| 知识更新时效               | 决定增量索引、缓存失效和降级策略 | 记录发布到可检索的端到端延迟       |
| 人工复核容量与升级时限     | 决定人在回路是否真实可用         | 统计队列、值班、响应和超时责任     |
| 质量、延迟和预算门槛       | 决定模型、重排、上下文和发布分级 | 在真实切片上比较候选方案           |

## 5. 推荐工作流

```text
知识发布
  -> 所有者、版本、生效时间、权限和结构校验
  -> 解析、切分、索引与增量更新
  -> 固定查询集回归与可检索状态发布

客户问题
  -> 身份、权限、产品与问题类型校验
  -> 查询改写候选
  -> 权限内混合检索与重排
  -> 检索充分性和知识冲突检查
  -> 基于证据生成回答草稿与主张级引用
  -> 引用支持、拒答和风险路由校验
  -> 坐席确认、修改、驳回或升级
  -> 发送并记录证据、版本、纠正与结果
```

停止继续生成或自动发送的条件包括：无权限、没有有效版本、检索为空、来源冲突、关键主张无支持、达到预算或重试上限、检测到提示注入风险、高风险问题需要授权人员、坐席已接管或任务已经完成。

## 6. 六个学习 Gate

### Gate 01：判断 AI 边界

- 问题：这个场景需要生成式回答，还是搜索与固定话术已经足够？
- 推荐：先建立权限内搜索和有效知识治理；只在需要跨片段归纳、语境适配和草稿表达时引入受限生成。
- 风险路径：直接把全部文档塞进长上下文，或用模型记忆回答动态政策。
- 材料：AI 适用性与不可自动化边界卡。

### Gate 02：建立价值与数据条件

- 问题：怎样证明解决的是“找到并使用正确知识”，而不是只让回答更像人？
- 推荐：记录当前任务完成、证据查找、升级、纠正和错误版本基线，再定义目标切片。
- 否决条件：没有知识所有者、没有权限模型、没有真实使用者或错误无法被追踪。
- 材料：客服知识机会评估表。

### Gate 03：拆解检索与回答工作流

- 问题：如何区分知识未进入索引、查询不匹配、重排失败和生成未遵循证据？
- 推荐：把知识发布、检索、重排、充分性判断、生成、引用和拒答分成可观察步骤。
- 风险路径：只用最终回答得分诊断整个 RAG 系统。
- 材料：RAG 诊断与方案选择表。

### Gate 04：设计坐席控制与失败恢复

- 问题：坐席怎样看见证据、识别不确定性、纠正回答并升级？
- 推荐：展示原文、版本和适用条件；允许修改、驳回和转交；高风险主题保持发送前确认。
- 风险路径：用一个“AI 生成”标签或免责声明替代真实控制。
- 材料：坐席权限、升级与恢复图。

### Gate 05：定义评测、成本与上线护栏

- 问题：怎样同时评测检索、回答、引用、拒答、延迟和人工负担？
- 推荐：使用版本化查询集和错误切片，分步测量检索相关性、答案忠实度、引用支持度和任务结果，并计算单位已确认回答成本。
- 风险路径：只看平均正确率、用户点赞或模型调用价格。
- 材料：RAG 评测、成本与上线护栏表。

### Gate 06：治理发布与持续更新

- 问题：什么时候能扩大自动化，知识更新或质量回退时如何停止？
- 推荐：离线回放、影子建议、坐席草稿、受限自动回复逐级推进；每级绑定知识新鲜度、风险切片、人工负担和回滚条件。
- 风险路径：首版直接面向全部客户自动回答。
- 材料：完整客服知识产品评审档案。

## 7. 失败与恢复矩阵

| 失败模式             | 可见信号                       | 默认恢复                               | 责任人           |
| -------------------- | ------------------------------ | -------------------------------------- | ---------------- |
| 过期文档仍可检索     | 引用旧版本或已下架政策         | 停止该来源、重建索引、回放受影响查询   | 知识负责人、工程 |
| 新知识未及时入索引   | 已发布内容持续无法召回         | 检查发布队列并回退到人工搜索           | 知识负责人、工程 |
| 权限过滤失败         | 返回其他租户或未授权内部资料   | 阻断输出、停用相关索引并启动事件响应   | 安全、工程       |
| 查询或召回失败       | 正确来源未进入候选             | 保留无答案并升级，不让生成层猜测       | 检索负责人       |
| 重排截断关键证据     | 相关来源被低排或未进入上下文   | 调整候选数与重排并运行位置切片回归     | 检索、评测负责人 |
| 引用存在但不支持主张 | 原文与回答结论不一致           | 阻止发送，重写或由坐席直接回答         | 坐席、评测负责人 |
| 知识来源互相冲突     | 多份有效文档给出不同规则       | 不自动选边，展示冲突并转知识负责人     | 知识负责人       |
| 无答案时仍然作答     | 缺少证据却给出确定回答         | 强制拒答并进入人工队列                 | 产品、坐席主管   |
| 间接提示注入         | 检索文档试图改变指令或调用工具 | 将内容按数据处理，阻止越权动作并隔离源 | 安全、工程       |
| 人工队列过载         | 队龄、积压和超时持续上升       | 收紧自动化范围并按影响分级             | 客服主管         |
| 版本升级质量回退     | 固定集或线上风险切片下降       | 冻结版本并回滚到上一稳定组合           | 产品、工程、评测 |

## 8. 评测与成本边界

### 8.1 分步评测

1. 知识发布：有效文档覆盖、版本正确、权限正确、更新延迟。
2. 检索：按主题和风险切片计算 recall、precision、无答案与冲突识别。
3. 生成：答案正确性、对证据的忠实度、关键主张覆盖和遗漏。
4. 引用：引用可打开、版本有效、位置准确且真正支持对应主张。
5. 拒答与升级：该拒答时拒答、该回答时不过度拒答，高风险进入正确责任人。
6. 任务：坐席是否更快形成可发送回答，修改、驳回、升级和重复联系是否改善。
7. 运行：成功率、队龄、P50/P95 延迟、降级、回滚和知识新鲜度。

自动评估可用于扩大覆盖，但不能代替真实坐席标注、风险切片审查和固定回归集。所有门槛继续保持 `E0 待验证`。

### 8.2 单位成功任务成本

```text
单位已确认回答成本 =
  （知识治理与索引 + 检索与重排 + 模型生成 + 失败重试与运行 + 人工复核）
  / 有充分证据且经授权坐席确认的回答数量
```

同时记录未回答、升级和错误恢复成本，避免通过过度拒答或减少覆盖伪造降本。

## 9. 分级上线与回滚

| 级别       | 系统权限                         | 通过依据                                 | 回滚动作                     |
| ---------- | -------------------------------- | ---------------------------------------- | ---------------------------- |
| 离线回放   | 只处理脱敏历史问题               | 分步错误可定位，权限与版本检查有效       | 停止实验                     |
| 影子建议   | 生成坐席不可见候选               | 与真实处理比较且不增加风险切片错误       | 关闭影子任务                 |
| 坐席草稿   | 坐席看见证据并确认后发送         | 任务结果、人工负担、成本与时延达到门槛   | 回到人工搜索或稳定版本       |
| 受限自动答 | 只覆盖已批准的低风险、高证据主题 | 持续满足引用、拒答、知识新鲜度和事件门槛 | 立即关闭自动发送并回到草稿态 |
