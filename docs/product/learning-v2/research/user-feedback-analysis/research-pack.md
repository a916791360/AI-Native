# 黄金项目研究包：每日用户反馈分析与产品改进

- 状态：`verified-for-content-model`
- 阶段：12A 案例研究 Gate
- 研究日期：2026-08-03
- 案例类型：教学案例，不代表任何真实公司的已上线系统或经营结果
- 来源登记：[`source-register.md`](./source-register.md)
- 后续用途：阶段 12B 内容 Schema、阶段 12C Huashu Design 三方向稿、阶段 13 生产纵向切片

## 1. 研究结论

这个案例不应被定义为“让大模型每天总结用户反馈”，而应被定义为：

> 在来源可追溯、错误可发现、人工可接管、成本可计算的前提下，把分散反馈整理成供产品团队复核的主题、问题证据和行动候选。

推荐方案不是自主 Agent，也不是一次 Prompt 包办全部工作，而是规则、受限模型步骤和人工决策组成的可观察工作流：

1. 规则负责输入校验、权限、精确去重、计数、状态和发布控制。
2. 模型负责语义分类候选、近似重复候选、主题聚类和有证据约束的摘要草稿。
3. 人工负责标签体系、歧义与高影响项、优先级、最终建议和发布。
4. 每个概率步骤单独评估，不用“整体看起来不错”替代质量证据。
5. 初次上线只进入影子运行，不直接替代当前流程。

## 2. 证据规则

本研究包使用以下标签，防止把教学设定写成真实业务事实：

| 标签          | 含义                                           | 使用方式                                 |
| ------------- | ---------------------------------------------- | ---------------------------------------- |
| `E3 外部事实` | 官方标准、官方指南或原始研究直接支持的通用原则 | 可作为方法依据，但不能证明本案例已经达标 |
| `E2 项目事实` | AI-Native 已批准的产品范围和学习契约           | 可直接进入内容模型                       |
| `E1 案例设定` | 为形成完整教学过程而设置的业务情境             | 页面必须明确标注为教学案例               |
| `E0 待验证`   | 需要真实组织数据、访谈或试运行才能回答         | 不填写数字，不写成已知结论               |
| `R 产品建议`  | 基于 E1-E3 形成的设计判断                      | 必须说明条件、风险和替代路径             |

任何基线、阈值、节省比例、准确率、成本或业务收益在没有真实数据时一律保持 `E0 待验证`。

## 3. 案例边界

### 3.1 教学场景

`E1 案例设定`：某数字产品团队从客服工单、应用商店评论和站内反馈中接收中文用户反馈。产品运营需要形成周期性反馈简报，产品经理据此发现高频问题、疑似 Bug 和体验机会。

### 3.2 目标角色

| 角色           | 在案例中的责任                   | AI 不替代的决定        |
| -------------- | -------------------------------- | ---------------------- |
| 产品运营       | 汇集反馈、复核标签、维护日常简报 | 是否接受分类和主题结果 |
| 产品经理       | 判断业务影响、优先级和后续动作   | 是否进入产品计划       |
| 客服或用户运营 | 提供原始语境和已知解决记录       | 是否需要立即响应用户   |
| 工程或数据人员 | 维护接入、日志、版本与回退       | 系统异常处置和技术发布 |
| 业务责任人     | 批准范围、预算和风险边界         | 是否扩大自动化范围     |

以上角色分工是 `E1 案例设定`，不是对所有组织结构的断言。

### 3.3 业务目标

`R 产品建议`：缩短从反馈产生到可复核问题证据出现的时间，同时提高纳入分析的反馈覆盖，并保持每条重要判断可以回到原文。

本案例不承诺：

- 自动找出所有真实 Bug。
- 自动决定产品优先级。
- 自动向用户或管理层发布结论。
- 用情绪、频次或模型分数直接代表业务价值。
- 仅凭生成式摘要证明效率或质量提升。

### 3.4 输入与输出

| 类型     | 候选内容                                                | 当前证据状态                   |
| -------- | ------------------------------------------------------- | ------------------------------ |
| 输入     | 客服工单、应用商店评论、站内反馈                        | `E1`，实际来源与访问权限待验证 |
| 输入字段 | 来源 ID、时间、文本、产品区域、已有标签、处理状态       | `E1`，真实字段完整性待验证     |
| 中间结果 | 规范化记录、重复候选、标签候选、主题候选、疑似 Bug 候选 | `R`                            |
| 输出     | 带原文证据的反馈简报和人工确认的行动候选                | `R`                            |
| 使用者   | 产品运营、产品经理、客服或用户运营                      | `E1`，真实受众待验证           |

## 4. 现状、基线与未知项

### 4.1 教学用当前流程

`E1 案例设定`：

```text
多来源导出
  -> 人工合并表格
  -> 人工去重与打标签
  -> 统计高频问题
  -> 阅读代表反馈
  -> 编写简报
  -> 产品经理复核并安排后续动作
```

这个流程只用于呈现可比较的教学起点。它不证明真实团队当前采用表格，也不证明人工流程一定低效。

### 4.2 上线前必须补齐的真实基线

| 未知项                 | 为什么影响方案                 | 最小取证方式                     |
| ---------------------- | ------------------------------ | -------------------------------- |
| 每个来源的反馈量与峰值 | 决定批处理、排队和抽样策略     | 统计历史分布，不只看平均值       |
| 当前处理耗时与等待时间 | 决定是否存在值得解决的问题     | 分开记录机器等待、人工处理和返工 |
| 重复与缺失比例         | 决定规则去重和数据治理优先级   | 对历史样本人工审查               |
| 标签体系与责任人       | 决定分类任务是否可定义         | 收集标签定义、反例和版本历史     |
| 高影响问题定义         | 决定假阴性的业务成本           | 与产品、客服、工程共同确认       |
| 原文中的敏感数据       | 决定脱敏、访问与保留策略       | 数据盘点和权限审查               |
| 简报如何触发行动       | 决定输出是否产生业务价值       | 跟踪接收、确认、建单和关闭链路   |
| 可接受预算与时效       | 决定模型、批次、降级和上线门槛 | 明确单位任务预算与业务时限       |

## 5. 推荐工作流

```text
来源接入
  -> 字段与权限校验
  -> 规范化、脱敏、精确去重
  -> 语义标签候选
  -> 近似重复与主题候选
  -> 疑似 Bug 和高影响项候选
  -> 证据约束的摘要与行动草稿
  -> 人工复核、修改或驳回
  -> 发布内部简报
  -> 记录纠正、行动与结果
  -> 更新评测集、标签体系和路由规则
```

`R 产品建议`：默认采用有固定步骤、固定输入输出和显式状态的工作流。只有在任务确实需要动态规划、工具选择和可控终止时，才重新评估是否引入 Agent。

### 5.1 状态与终止条件

| 状态           | 进入条件                   | 正常退出             | 异常退出             |
| -------------- | -------------------------- | -------------------- | -------------------- |
| `ingested`     | 来源记录通过身份与权限检查 | 进入规范化           | 拒绝并记录原因       |
| `normalized`   | 必要字段可解析             | 进入分析             | 进入缺失字段队列     |
| `analyzed`     | 所有启用步骤返回结构化结果 | 进入复核             | 重试、降级或人工队列 |
| `needs-review` | 存在低确定性、高影响或冲突 | 人工接受、修改或驳回 | 超时升级给责任人     |
| `approved`     | 人工确认简报与证据         | 发布内部简报         | 撤回到复核状态       |
| `closed`       | 结果已记录且关联行动可追踪 | 进入历史与评测样本   | 保持未关闭并提示缺口 |

停止继续调用模型的条件包括：输入无权限、必要字段缺失、预算或重试上限达到、输出无法通过结构校验、证据链接缺失、人工已接管或任务已经完成。

## 6. 规则、模型与人工边界

| 任务                         | 首选机制               | 原因                     | 何时升级                       |
| ---------------------------- | ---------------------- | ------------------------ | ------------------------------ |
| 字段格式、来源许可、时间范围 | 规则                   | 条件确定且需要可审计     | 规则无法覆盖的来源异常交人工   |
| 精确重复、固定黑名单、计数   | 规则                   | 结果可复现，成本低       | 近似表达再交语义模型           |
| 语义多标签候选               | 小型可评估模型         | 文本表达存在变化         | 高影响或低质量切片交人工       |
| 近似重复候选                 | 嵌入或受限模型         | 需要语义相似度           | 只输出候选，不自动删除记录     |
| 主题聚类                     | 受限模型步骤           | 主题数量和表达会变化     | 新主题、合并和拆分由人工确认   |
| Bug 候选发现                 | 规则信号加模型分类     | 需要结合词义与结构信号   | 高严重度候选必须人工确认和建单 |
| 简报摘要                     | 有证据约束的模型草稿   | 可压缩大量文本           | 无原文证据或有冲突时禁止发布   |
| 产品优化建议                 | 人工主导，模型提供候选 | 需要业务、成本与战略判断 | 不允许模型自动进入路线图       |
| 发布、外发、优先级和关闭     | 人工与权限系统         | 影响真实业务和责任归属   | 不向模型下放最终权限           |

### 6.1 被否决的三种捷径

1. **全部使用规则**：适合稳定分类和明确词表，但无法可靠覆盖语义变化和新主题。
2. **单次大模型调用完成全流程**：难以定位哪一步失败，也难以分别控制质量、成本和恢复。
3. **自主 Agent 直接生成并发布简报**：当前任务步骤可预定义，动态自主性没有被证明，反而扩大权限、终止和审计风险。

## 7. 六个学习 Gate

### Gate 01：是否需要 AI

- 决策问题：哪些步骤真的需要概率语义能力？
- 已知依据：输入校验、精确去重、计数和发布权限可以确定性实现；语义分类和主题发现存在表达变化。
- 推荐：规则先行，只在语义步骤引入模型，不默认使用 Agent。
- 待验证：现有标签规则的覆盖、未知表达比例、误判成本。
- 材料增量：AI 适用性判断卡。

### Gate 02：业务价值与数据条件

- 决策问题：怎样证明这不是一个“更漂亮的摘要 Demo”？
- 推荐：先记录当前处理时间、覆盖、返工、问题发现和行动链路，再定义可观察目标。
- 待验证：实际量级、数据许可、标签一致性、简报是否触发真实行动。
- 否决条件：没有明确使用者、没有当前基线、没有原文权限或输出不触发任何决策。
- 材料增量：场景机会评估表。

### Gate 03：任务拆解与方案选择

- 决策问题：如何让每一步可评估、可替换、可停止？
- 推荐：采用固定工作流；每步使用结构化输入输出、版本和状态；不把动态规划当作默认能力。
- 待验证：标签任务是单标签还是多标签、主题更新频率、是否需要跨来源身份合并。
- 材料增量：任务流程与方案选择表。

### Gate 04：人机协作与失败恢复

- 决策问题：失败出现时谁能看见、纠正、接管和恢复？
- 推荐：低确定性、高影响、冲突和无证据内容进入人工队列；保留原文、步骤结果、版本和失败原因。
- 待验证：人工复核容量、响应时间、升级责任人和业务连续性要求。
- 材料增量：人机责任与失败恢复图。

### Gate 05：评测、成本与上线治理

- 决策问题：怎样证明质量、时效和成本同时可接受？
- 推荐：建立任务级黄金集、错误切片、在线运行指标和单位成功任务成本；门槛由真实基线与错误成本决定。
- 待验证：各类错误成本、预算、时效、上线与回滚阈值。
- 材料增量：评测计划、成本表和上线护栏表。

### Gate 06：完整项目与持续迭代

- 决策问题：什么时候扩大范围，什么时候停止或回滚？
- 推荐：影子运行、辅助草稿、有限使用、扩大范围四级推进；每级保留责任人、通过条件和回滚路径。
- 待验证：实际使用者行为、纠正数据是否代表真实质量、行动是否改善业务结果。
- 材料增量：完整 AI 产品评审档案。

## 8. 失败与恢复矩阵

| 失败模式               | 可见信号                   | 影响               | 默认恢复                                   | 人工责任             |
| ---------------------- | -------------------------- | ------------------ | ------------------------------------------ | -------------------- |
| 来源接口失败或限流     | 批次缺口、错误码、队列积压 | 简报不完整         | 重试、延迟批次、标记缺失来源               | 工程确认恢复与补采   |
| 字段缺失或格式变化     | Schema 校验失败            | 记录丢失或错配     | 隔离记录，不进入模型                       | 数据责任人修复映射   |
| 敏感数据未脱敏         | 检测或审查告警             | 隐私与权限风险     | 停止处理并隔离                             | 安全或数据责任人处置 |
| 精确或近似重复误判     | 重复率异常、人工驳回       | 频次失真、证据丢失 | 不删除原文，只撤销合并关系                 | 运营确认合并边界     |
| 标签漂移               | 分布变化、旧样本回归失败   | 分类失真           | 回退标签版本、进入重标队列                 | 标签责任人批准新版   |
| 分类假阳性             | 错误进入某类               | 人工噪声、错误升级 | 降低自动路由权限                           | 运营纠正标签         |
| 高影响问题假阴性       | 后续人工或事件发现遗漏     | 重大问题延迟       | 提高相关切片召回、增加规则信号             | 产品与工程复盘       |
| 主题错误合并或拆分     | 主题不稳定、证据互相冲突   | 趋势误读           | 展开原文、允许人工重组                     | 产品运营确认主题     |
| 幻觉建议或无证据摘要   | 结论没有原文引用           | 错误决策           | 阻止发布、重新生成或人工编写               | 产品经理最终签发     |
| 模型超时或供应商不可用 | 超时、失败率升高           | 批次延迟           | 跳过非必要步骤、使用上次稳定版本或人工流程 | 工程决定降级         |
| 提示、模型或版本变化   | 固定集回归下降             | 无声质量漂移       | 冻结版本、阻止晋级                         | 产品与工程共同批准   |
| 人工队列过载           | 队龄和积压升高             | “人在回路”失效     | 收紧自动处理范围、按风险排序               | 业务责任人调配容量   |
| 纠正反馈被错误解释     | 指标改善但实际质量下降     | 形成错误闭环       | 区分修改、驳回和业务偏好                   | 评测责任人校准标签   |

## 9. 评测计划

### 9.1 评测对象

工作流必须分步评估：

1. 输入完整性与来源覆盖。
2. 精确和近似重复候选。
3. 多标签分类。
4. 主题聚类与主题稳定性。
5. 疑似 Bug 和高影响问题发现。
6. 摘要的证据覆盖、事实一致和可执行性。
7. 端到端简报是否帮助真实使用者完成判断。

### 9.2 数据集

`R 产品建议`：建立版本化黄金集，包含常见样本、边界样本、高影响少数类、来源切片、语言表达变化和历史失败。标签由业务人员定义，并记录分歧；生产纠正只有在确认含义后才进入黄金集。

不得只使用开发者自己编写的顺利样本，也不得把模型生成标签直接当作真实答案。

### 9.3 指标候选

| 层级       | 指标候选                                                                   | 解释边界                             |
| ---------- | -------------------------------------------------------------------------- | ------------------------------------ |
| 业务       | 简报交付周期、纳入复核的反馈覆盖、确认问题发现周期、行动候选采纳与后续结果 | 先记录基线；采纳不等于业务成功       |
| 分类       | 各标签 precision、recall、F1、混淆矩阵                                     | 类别不平衡时不以总体 accuracy 代替   |
| 高影响发现 | 高影响切片 recall、漏报案例数与发现时延                                    | 假阴性成本高时优先看召回             |
| 去重       | 候选对 precision、recall、被错误合并的原文数量                             | 原文保留，避免不可逆删除             |
| 主题       | 主题覆盖、人工可解释性、跨批次稳定性、合并拆分率                           | 聚类没有唯一标准答案，需人工判断     |
| 摘要       | 原文证据覆盖、无依据主张率、事实一致、关键信息遗漏                         | 文风好看不能替代证据正确             |
| 运行       | 成功率、重试与降级率、队列时长、P50/P95 延迟                               | 平均值不能掩盖长尾和来源缺口         |
| 人工       | 复核量、单项复核时间、修改率、驳回率、积压时长                             | 低修改率可能是盲信，不自动代表高质量 |
| 成本       | 单位成功记录成本、单位已批准简报成本、失败与重试成本                       | 不只记录模型调用价格                 |

所有数值阈值当前均为 `E0 待验证`。阶段 12B 只建字段，不填虚构目标值。

## 10. 成本模型

单位成功任务成本建议按下式记录：

```text
单位已批准简报成本 =
  （接入与预处理 + 模型调用 + 重试与失败 + 存储与运行 + 人工复核）
  / 已批准且证据完整的简报数量
```

同时保留单位反馈记录成本，防止通过减少处理覆盖来伪造降本。

成本优化顺序：

1. 删除没有业务价值的模型调用。
2. 用规则处理确定性任务。
3. 合并可安全合并的步骤，减少往返和重复上下文。
4. 对批处理使用合适的异步路径。
5. 在固定评测集上验证更小模型或更短输入输出。
6. 设置预算、重试和批次上限；达到上限时降级而不是无限调用。

模型、价格和供应商当前不冻结。具体选型必须在真实数据和预算下比较。

## 11. 上线与回滚路径

| 级别     | 系统权限                     | 通过依据                             | 回滚动作                   |
| -------- | ---------------------------- | ------------------------------------ | -------------------------- |
| 影子运行 | 读取副本并产出不可见结果     | 与现行流程比较，错误可归因           | 停止批次，不影响现行业务   |
| 辅助草稿 | 向指定复核者展示候选         | 质量、人工负担和证据链达到已批准门槛 | 回到影子运行或人工流程     |
| 有限使用 | 在有限来源或低风险类别中使用 | 线上指标、成本和恢复演练通过         | 冻结版本并缩小范围         |
| 扩大范围 | 扩展来源、类别或使用者       | 每次扩展重新评估数据和失败切片       | 按来源、类别或版本局部回退 |

任何一级都不得因为“流程跑通”自动晋级。以下情况默认阻止晋级或触发回滚：来源与证据缺失、高影响问题漏报不可控、人工队列失去响应、成本超出已批准预算、敏感数据事故、版本变化未通过回归或无法恢复到人工流程。

## 12. 阶段 12B 冻结输入

以下内容可以进入内容 Schema：

- 案例稳定 ID：`user-feedback-analysis`
- 案例级别：`capstone`
- 六个有顺序的 Gate 及其决策问题。
- 规则、模型、人工三类责任边界。
- 六类标准材料及逐关卡增量。
- 失败模式、恢复动作、责任角色和观测信号。
- 业务、质量、运行、人工和成本五类指标。
- `fact`、`assumption`、`unknown`、`recommendation` 四类主张。
- 来源 ID、支持范围、日期和稳定性说明。
- 影子运行到扩大范围的四级发布状态。

以下内容不得在 12B 中伪造：

- 真实公司、品牌、用户量、工单量或团队规模。
- 真实处理时间、节省比例、准确率、成本和收益。
- 未经验证的数据许可、标签质量和人工容量。
- 特定供应商是最佳选择的结论。
- 系统已经上线、已经产生业务结果或已经通过用户验证的表述。

## 13. 仍需真实项目回答的问题

1. 实际反馈来源、语言、字段、访问权限和保留期限是什么？
2. 当前谁处理反馈，耗时、等待、返工和覆盖基线是多少？
3. 哪些类别最重要，标签由谁定义和更新？
4. 哪种漏报或误报最昂贵，业务后果是什么？
5. 简报由谁阅读，如何形成建单、优先级和关闭证据？
6. 人工每天能复核多少，超时升级给谁？
7. 单位成功任务预算和可接受时效是什么？
8. 哪些数据不能发送给外部模型，哪些必须脱敏？
9. 何种质量、成本和恢复证据允许从影子运行晋级？
10. 谁拥有停止、回滚、标签变更和最终发布权限？

这些问题不是研究包的缺陷，而是本案例需要教会用户保留的未知项。
