# Learning System V2 阶段 12C 视觉 Gate 共同规格

## 任务定义

本轮只为新的 Level 2 连续案例和 Level 3 完整项目选择信息结构，不修改 Astro 生产页面。三套方案必须使用同一个真实内容事实源 `src/content/cases/user-feedback-analysis.yml`，分别制作一个可通过 `file://` 独立打开的完整 HTML，并在 1440x900 与 390x844 两个视口验证。展示三套方案后停止，由用户选择或提出混合意见；未获得选择前，不创建生产组件、不修改正式路由、不把案例状态从 `draft` 改为 `published`。

## 产品问题

现有 24 题适合训练单点判断，但用户仍难以理解这些判断如何在一个真实项目里连续发生。新的案例体验必须让第一次进入的用户在首屏内回答五个问题：这是什么案例、为什么值得学、现在从哪一关开始、每一关要做什么判断、走完会得到哪些可复用材料。它不是词条浏览页、考试系统或要求用户交作业的工作台，而是一套通过阅读情境、选择方案、展开反馈、比较后果和查看材料演进完成的案例课程。

## 用户与任务

- 核心用户：准备转型 AI 产品经理的中文初学者，以及希望补齐落地方法的初级产品经理。
- 用户目标：在同一个业务对象中学会判断 AI 是否适用、定义业务机会、拆解方案、设计人机责任与失败恢复、建立评测和成本口径、治理上线与迭代。
- 黄金案例：每日用户反馈分析与产品改进。
- 起点：Gate 01「先判断是否需要 AI」。
- 终点：一份可复核的「完整 AI 产品评审档案」。
- 学习机制：阅读、单选、展开、前后比较；不要求文字输入，不登录，不保存个人进度，不伪装完成状态。

## 固定内容结构

三版必须完整呈现六个 Gate，并保持事实源顺序：

1. 先判断是否需要 AI。
2. 定义业务机会与约束。
3. 拆解任务并选择方案。
4. 设计人机责任与失败恢复。
5. 定义评测、成本与护栏。
6. 治理上线与持续迭代。

每个 Gate 至少暴露标题、核心问题、推荐决策、一条关键事实、一条未知项、三条可选路径及其 recommended/conditional/risky 反馈，以及本关对学习材料产生的变化。材料沿流程逐步增加：AI 适用性判断卡、场景机会评估表、任务流程与方案选择表、人机责任与失败恢复图、评测成本与上线护栏表、完整 AI 产品评审档案。

## 首屏信息优先级

1. 第一优先级：明确这是一个连续案例，不是 24 题的重复入口。
2. 第二优先级：只提供一个主起点，文案统一为「从 Gate 01 开始案例」。
3. 第三优先级：展示六关结构与最终产物，但不得让六个 Gate 看起来像六道可随意切换的下一题标签。
4. 第四优先级：说明学习无需输入或保存进度，选择只用于查看即时反馈。
5. 第五优先级：词条、路线、来源和指标是按需展开的证据层，不抢主任务。

## 交互要求

- 主按钮进入或聚焦 Gate 01。
- Gate 导航必须表达「项目阶段」，不能伪装题号或个人进度。
- 用户选择方案后在当前页面显示推荐、有条件成立或风险较高的解释；允许重选，不记录历史。
- 至少有一个「查看本关如何改变材料」的展开交互，展示前后差异或新增字段。
- 必须能查看完整六关档案概览，但该入口是次要命令。
- 键盘可操作，焦点可见，触控目标至少 44px；移动端无横向溢出。

## 视觉继承与限制

- 继承已批准的方向 1「深空知识展柜」：近黑基底、暖白正文、编辑式编号、1px 规则线、Baskerville/宋体标题、Avenir Next/苹方正文和等宽元信息。
- 黄色表示起点与前置判断，青色表示结构与机制，红色表示风险与比较，绿色表示实践、恢复与可行动结果。
- 色彩从现有 Token 与案例语义采样并收敛，不引入通用紫蓝渐变、霓虹光球或无意义装饰色。
- 不使用卡片套卡片，不把页面章节做成漂浮卡片，不用圆角药丸承载普通文本。
- 不使用虚构完成率、学习时长、用户评价、业务提升数字或已验证阈值。所有未知阈值明确标记「待真实基线」。
- 不使用装饰性 AI 插画。这个界面的核心对象是决策、证据和材料演进，图像会降低可审计性；视觉资产仅允许由 HTML/CSS 规则线、轨道、编号和结构图构成。
- 中文正文桌面 17px 左右、移动端至少 16px，行高不低于 1.65；大标题不得遮挡相邻内容，汉字字距为 0。

## 三个方向

### 方向 01「连续评审脊柱」

真实世界参考逻辑：借鉴 GOV.UK Step by step navigation 对有明确起点、终点和固定顺序的端到端旅程组织方式，并参考 Carbon Design System 对纵向步骤易读性的建议。只借鉴任务顺序、展开层级和可访问性原则，视觉仍完全使用 AI-Native 深空体系。桌面采用左侧项目导言、中部纵向六关脊柱、右侧当前关摘要；移动端线性折叠为导言、唯一主按钮、当前关、后续关预览。

- GOV.UK 官方参考：<https://design-system.service.gov.uk/patterns/step-by-step-navigation/>
- Carbon 官方参考：<https://carbondesignsystem.com/components/progress-indicator/usage/>

### 方向 02「证据决策台」

设计哲学逻辑：采用 Edward Tufte 的高信息密度、直接标注和尽量消除非数据装饰的原则，把案例做成可审计的决策工作台。桌面首屏同时展示业务情境、三种方案、证据/未知项和材料变化；六关以档案目录存在，不占据顶部切换区。重点检验专业感与信息清晰度能否共存，避免传统仪表盘式卡片堆叠。

- Edward Tufte 官方参考：<https://www.edwardtufte.com/book/beautiful-evidence/>
- 相邻信息比较原则：<https://www.edwardtufte.com/notebook/lists-design-and-construction-by-edward-tufte/>

### 方向 03「能力星图」

Huashu 秒数轮盘逻辑：秒数 `06` 映射网页风格库第 7 项「复古未来太空图录」。用低饱和黑、暖白、钴蓝和现有关系色，把六个 Gate 画成围绕同一业务对象推进的轨道，不使用渐变或装饰行星图；每一条轨道都必须对应真实关卡、材料或证据关系。重点检验更强品牌辨识度是否仍能提供清晰起点和线性阅读。

## 验收问题

每个方向截图前必须回答：

1. 新用户能否在 5 秒内指出唯一开始入口？
2. 是否能分辨六个 Gate 是一个项目的连续阶段，而不是六道并列题目？
3. 是否能理解选择行为只用于看反馈，不要求提交作业或保存进度？
4. 是否能看见材料如何随着每一关逐步完善？
5. 是否能从当前决策回到事实、未知项、失败模式和参考词条，而不被信息淹没？
