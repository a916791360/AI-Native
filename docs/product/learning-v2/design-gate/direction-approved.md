## 生产转译约束

- 阶段 13 的连续案例页和完整项目档案采用方向 02「证据决策台」的信息结构。
- 生产代码继续继承既有方向 1「深空知识展柜」的 Token、站点 Header、规则线、字体层级、焦点和四色语义，不把原型复制成独立视觉孤岛。
- 案例事实只能来自 `src/content/cases/user-feedback-analysis.yml` 及其确定性生成物，不在页面中维护第二份内容。
- 首屏必须同时回答案例是什么、从哪里开始、用户如何学习、六关最终形成什么材料。
- Gate 01 采用情境、三种决策、事实与未知项、即时反馈、材料变化的同屏结构；后续 Gate 复用同一结构契约。
- 六个 Gate 作为完整项目档案目录存在，不放在顶部做并列题目切换，不暗示已完成状态。
- 用户只阅读、选择、展开和比较；不输入长文本、不登录、不保存个人选择或进度。
- 规则、模型、人工责任、失败恢复、评测、成本和上线边界不得被视觉简化掉；所有未验证阈值继续标记为待真实基线。
- 原型 HTML 只作为设计依据。正式实现必须拆分为 Astro 页面、共享组件、客户端最小交互和可测试数据适配层。
