# AI-Native 学习体系 V2 实施计划

- 状态：已批准，阶段 12B 已完成，当前进入 12C
- 批准日期：2026-08-03
- 产品规格：[`product-spec.md`](./product-spec.md)
- 技术基线：Astro 静态站、现有内容 Schema、Pagefind、Cytoscape 和统一 CI
- 部署边界：阶段 16 之前不得部署；阶段 16 仍需用户新的明确授权

## 1. 实施原则

1. 保留现有技术和内容资产，不重建工程。
2. 先完成内容契约和黄金案例，再设计新增页面。
3. 24 道题继续运行，但不再被描述为完整职业课程。
4. 新交互不要求文本输入、不保存个人选择或进度。
5. 每个阶段必须有可观察产物、自动门禁和人工 Gate。
6. 推送 GitHub、创建 PR 和部署仍分别需要用户明确授权。

## 2. 阶段关系

```text
阶段 10 技术发布候选基线
  → 阶段 11 V2 产品定义与内容契约
  → 阶段 12 黄金项目研究 + Huashu Design Gate
  → 阶段 13 黄金项目生产纵向切片
  → 阶段 14 重点案例与阅读支持扩展
  → 阶段 15 目标用户任务验收与发布候选
  → 阶段 16 部署决策与发布（需再次授权）
```

阶段 10 的性能、无障碍、搜索、图谱和内容质量证据继续作为技术基线；原任务型验收被 V2 新范围替代，不再用旧验收关闭产品发布 Gate。

## 4. 阶段 12：黄金项目研究与视觉 Gate

### 目标

为“每日用户反馈分析与产品改进”建立可核验内容包，并确定连续案例页和完整项目页的生产信息结构。

### 12A：案例研究 Gate

- [x] 明确目标角色、当前流程、输入来源、输出使用者和业务结果。
- [x] 建立六个评审关卡的事实、假设、未知项和来源。
- [x] 为规则、模型和人工的边界准备可比较方案。
- [x] 建立失败清单：接口失败、重复、缺失、标签漂移、错误聚类、幻觉建议、超时和人工接管。
- [x] 定义指标口径候选：分类质量、主题覆盖、Bug 发现、人工时间、单位处理成本和延迟。
- [x] 不具备真实证据的数字保持待验证。

产物：[`research/user-feedback-analysis/research-pack.md`](./research/user-feedback-analysis/research-pack.md) 与 [`research/user-feedback-analysis/source-register.md`](./research/user-feedback-analysis/source-register.md)。

### 12B：内容模型 Gate

- [x] 定义 case、gate、option、artifact、metric、failure mode 和 reference 类型。
- [x] 校验稳定 ID、关卡顺序、阶段引用、案例状态和知识引用。
- [x] 生成案例注册表和静态导航数据。
- [x] 建立无效引用、重复关卡、缺少失败项和状态不一致的固定反例测试。

产物：`src/content/cases/user-feedback-analysis.yml`、`src/lib/cases/`、`src/generated/case-registry.json`、`src/generated/case-navigation.json` 与 `tests/unit/cases/model.test.ts`。

### 12C：Huashu Design Gate

1. 使用 `$huashu-design`，基于同一份黄金项目真实内容制作三套 HTML 方向稿。
2. 每套必须包含连续案例首屏、决策反馈、材料演进和完整档案视图。
3. 每套输出桌面 1440x900 与手机 390x844 截图。
4. 三套均继承深空知识展柜 Token，只探索信息组织和交互节奏。
5. 展示后停止，等待用户选择；未选择前不修改生产页面。

### 出口标准

- 黄金项目内容包可被逐项复核。
- 内容 Schema 和失败测试通过。
- 用户选定一套新增页面方向并记录原话。

## 5. 阶段 13：黄金项目生产纵向切片

### 目标

在 Astro 生产站中完成一条从基础判断进入完整项目、再按需查阅知识的真实闭环。

### 任务

1. 实现案例数据加载、静态路径和状态展示。
2. 实现连续案例页、关卡位置、选择反馈和材料变化。
3. 实现完整项目档案页或同页档案视图。
4. 更新首页和学习中心，解释 Level 1–3 的关系并保持唯一默认起点。
5. 将现有 24 题明确标记为基础判断层。
6. 将相关词条、阅读路线和图谱作为当前关卡的按需支持。
7. 增加无 JavaScript 默认路径、键盘、屏幕阅读器和减少动画支持。
8. 增加桌面、平板、手机和 320px 窄屏截图检查。

### 自动门禁

```bash
pnpm format:check
pnpm lint
pnpm check
pnpm validate:data
pnpm check:generated
pnpm test:unit
pnpm build
pnpm check:performance
pnpm test:e2e
```

### 出口标准

- 用户不输入文字即可完成六个关卡。
- 每个选择都展示价值、条件、风险和材料变化。
- 同一项目在六个阶段中保持对象、流程和责任一致。
- 禁用 JavaScript 后仍能阅读推荐路径、标准材料和来源。
- 首页不恢复多主入口，性能不突破已批准预算。

## 6. 阶段 14：重点案例与阅读支持扩展

### 目标

把黄金项目验证过的内容和页面模式扩展到五个重点案例，并补齐六阶段知识支持。

### 案例批次

1. 客服知识库：动态知识、引用、检索失败和人工确认。
2. 销售跟进助手：上下文整理、外发权限、错误承诺和关系风险。
3. 合同条款审核：高风险证据、漏报误报和责任边界。
4. 内容生产：生成价值、品牌约束、审核、版本和发布风险。
5. 内部运营自动化：规则、工作流、Agent、自主性和系统失败。

每个案例依次经过：选题与范围 Gate → 研究包 → 初稿 → 来源与边界核验 → 生产发布。未核验案例不得显示为完整深度案例。

### 阅读支持

新增或重组以下学习支持，不以增加词条数量为目标：

- 规则、搜索、工作流与 AI 的取舍。
- Agent 任务拆解、工具、状态和终止条件。
- RAG 失败定位与评测。
- 人机权限、恢复和事件升级。
- 单位成功任务成本、模型路由和延迟预算。
- 上线监控、灰度、回滚和持续迭代。

### 出口标准

- V2 首批 1 个完整项目和 5 个重点案例全部达到已核验状态。
- 六阶段各自至少有一条连续案例覆盖。
- 用户从案例可直接进入必要词条和阅读支持，再返回原关卡。
- 现有 300 词条和关系生成物没有断链或生命周期漂移。

## 7. 阶段 15：目标用户验收与 V2 发布候选

### 目标

验证用户是否真正理解学习结构并产生能力迁移，而不是只验证页面能否点击。

### 参与者

至少 5 名符合第一用户画像的参与者。记录任务完成、耗时、卡点、误解和原话摘要，不收集无关个人信息。

### 任务

1. 找到唯一默认起点，并说明 Level 1–3 的差异。
2. 连续完成一个四题基础阶段并解释一个取舍原则。
3. 完成黄金项目六个关卡，不填写文字。
4. 说明反馈分析流程中哪些步骤使用规则、模型和人工。
5. 指出至少一个失败、恢复路径、质量指标和成本口径。
6. 根据完整档案说明方案何时可以上线、何时应回滚。
7. 按需查阅一个词条或路线并返回原案例位置。

### 记录与处理

- 阻断：无法开始、无法继续、主要内容不可访问或核心定义错误。
- 严重：误解主课程结构、把错误方案当成推荐路径、无法识别失败与上线边界。
- 一般：文案、密度、定位或次要导航问题。

所有阻断和严重问题处理完毕后，重新执行受影响任务。首次样本只用于发现问题，不声称统计代表性。

### 出口标准

- 所有自动质量命令通过。
- 五类核心能力均有任务证据。
- 阻断和严重问题归零。
- 形成新的 V2 固定截图、性能基线、已知问题和回滚说明。
- 仅生成本地发布候选，不执行部署。

## 8. 阶段 16：部署决策与发布

此阶段必须获得用户新的明确授权后才能执行。

### 发布前决策

1. 网站公开还是限制访问。
2. 托管平台、正式 HTTPS 地址、子路径和 404 策略。
3. 源代码仓库可见性。
4. 是否启用匿名、最小化分析；默认不启用。
5. 内容纠错入口是否对目标用户可用。

### 发布任务

1. 创建独立、最小权限的部署工作流。
2. 在测试环境验证 canonical、Open Graph、sitemap、robots、Pagefind 和图谱资源路径。
3. 执行阶段 15 的完整发布候选门禁。
4. 首次发布后执行桌面、手机、课程、案例、搜索、图谱、来源和纠错链接冒烟测试。
5. 记录发布版本、提交、时间、监控方式和回滚步骤。

## 9. 每阶段检查点

每个阶段结束时：

1. 更新产品事实、决策日志和当前状态。
2. 运行与变更范围匹配的自动门禁。
3. 检查生成物和文档中的旧状态、旧数量与旧阶段编号。
4. 审查 Git 差异，确保没有无关文件。
5. 只有用户明确要求时才提交或推送 GitHub。
