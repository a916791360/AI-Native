# AI-Native 品牌上下文（方向探索阶段）

- 品牌名称：AI-Native
- 品牌定位：面向中文 AI 初学者与产品人的渐进式 AI 知识图鉴
- 核心承诺：从听懂 AI，到能够判断业务场景并设计基本 AI 方案
- 首发内容：AI 通识与模型认知、提示词与人机协作、AI 产品与场景判断、RAG 进阶专题
- 现有资产：AI-Native 8×8 Logo Mark、确定性内容模型与现有 Astro 组件
- 当前标识策略：使用既有 Logo Mark 与「AI-Native」文字标识
- 参考来源：VibeHub 的搜索、分类、左侧目录和卡片网格结构；不复制其品牌名称与专有资产
- 视觉禁区：通用紫色渐变、霓虹科技模板、装饰性图标、虚构数据、堆叠式 Bento 卡片、重绘的界面外壳
- 当前生产方向：B「清晰内容台」返工版，以单层顶栏、搜索、内容域、左侧目录和右侧卡片网格作为不可变骨架
- 设计母题：内容目录；用户先扫描真实内容，再进入判断题、案例或知识支持
- 发现入口：首页讲清定位与三层学习结构，系统课程直接展示三层 × 六阶段、90 题目录；案例库与知识库保持全局一级入口，不再增加任务轨道或重复说明页。
- 全局壳层：所有正常内页共享单层顶栏与常驻搜索；正文之上只有这一层导航，不允许再出现水平内容分类条。支撑层（阅读路线、概念图谱、搜索、内容方法）只出现在页脚。404 页只保留顶栏与恢复动作。
- 板块命名：`src/config/sections.ts` 是板块名称的唯一事实源（导航标签、页面标题、一句话定位同源）。同一板块在顶栏、页面 H1 与页脚中必须同名；改名只需改这一处，禁止为同一批内容维护第二套名词。
- 详情页规则：系统课程内页、案例页、词条、路线、图谱和内容方法均使用约束内容宽度、紧凑一级标题、规则线和不超过 8px 的圆角；禁止恢复超大编辑式标题或整屏叙事分带。
- 顶栏分组：开始学习、案例库和知识库是三个同级入口，位于同一主导航；首页由左上角 wordmark 承担，不占导航位；搜索是唯一右侧辅助控件。阅读路线、概念图谱与搜索下沉到页脚，作为「按需查阅」的支撑层，不再占用顶栏。
- 控件密度：桌面顶栏搜索宽度不超过 288px、高度不超过 40px；搜索页和图鉴内搜索保持 480px 以内的内容宽度，移动端才使用可用整行。
- 间距基线：全局使用 90rem 内容上限与 8px 间距基线；常规卡片内边距以 16-24px 为主，详情页首屏不使用遗留的 48-72px 展示型留白。
- 编号规则：题号、路线号和章节号只承担定位，不作为装饰性巨型文字；列表卡片中的路线号使用紧凑元数据行。
- 首页 hero：右侧只讲「方法」（每一题都在回答哪三个判断问题），不展示某一道具体题的题面与答案，也不展示 24 题目录；不使用重绘的终端/浏览器窗口外壳（三个圆点 + 假标题栏）与虚构命令行，容器只允许上下一道细线的排版框。
- 答题交互：一题一屏，作答即就地展开该题全部路径的判断依据，不跳转到页面下方的独立反馈面板；核心原则默认收起、答完展开，但在禁用 JavaScript 时保持可读；同一题只接受一次作答，不允许「试到对为止」。键盘 1–N 作答，答完后 → 进入下一题。
- 难度契约：三层（T1 概念识别 / T2 场景判断 / T3 权衡取舍）各自有可度量的题面契约（条件数、选项数、有条件成立项与高风险项的下限），由 `pnpm check:learning` 逐题校验；正确答案在渲染时按题目 id 稳定打散，任何单一位置的占比不得超过 40%。
- 进度与解锁：进度只记录在本机浏览器；三层依次解锁，上一层全部答完才开启下一层，解锁不隐藏内容，只改变进入顺序与提示文案。
