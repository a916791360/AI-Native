# AI-Native 产品体检与「转岗 AI 产品经理」改造计划

> 体检人视角：一名想转岗 AI 产品经理的产品经理（初级）。
> 体检对象：`AI-Native` 静态学习站点（本地构建 352 页，`main@015a21b`）。
> 体检日期：2026-08-13。
> 结论：**作为「AI 产品判断力」学习库，质量优秀；但作为「转岗 AI 产品经理」的学习入口，目前不达标，需要改造。**

---

## 2. 现状盘点

### 2.1 信息架构

主导航：`首页 / 系统课程 / 案例库 / 知识图鉴 / 阅读路线 / 概念图谱 / 搜索`。

内容规模（来自 `ContentScopeNav` 与 `deriveSiteMetrics`）：

- 系统课程 24 题；案例实战 2；知识词条 300；阅读路线 4；概念关系 308。

### 2.2 学习体系（六阶段）

| 阶段 | 标题              | 核心决策问题                       | 学习产出                 |
| ---- | ----------------- | ---------------------------------- | ------------------------ |
| 01   | AI 基础与模型边界 | 这个问题是否真的需要 AI？          | 识别生成、规则与模型边界 |
| 02   | 场景与机会判断    | 这个机会值得做、能够做吗？         | 建立场景筛选标准         |
| 03   | 方案选择          | 哪种方案最小、可靠且可验证？       | 做出有依据的技术取舍     |
| 04   | AI 产品体验       | 人和 AI 分别在什么时候做决定？     | 形成可靠的人机协作体验   |
| 05   | 质量与商业约束    | 怎样证明它长期可用且值得运行？     | 建立上线与运营门槛       |
| 06   | 综合产品项目      | 这份方案能否经得住业务与技术评审？ | 完成端到端产品判断       |

### 2.3 内容生命周期与诚实性

- 325 词条均为 `verified`（8 段正文 + 双来源 + 发布/更新/核验日期）。
- 2026-08-20 追记：原先的 220 篇 `catalogued` 已全部补完；下方按域分布表保留 2026-08-13 体检快照。
- 来源优先级五档（原始研究/规范 > 官方文档 > 教材机构 > 工程实践 > 媒体观点）。
- 案例阈值一律 `待真实基线`，不虚构数字；`已收录/草稿/已核验/需复核/已弃用` 状态清晰。

### 2.4 视觉系统

- 浅色「明亮内容工作台」：`oklch` 中性色 + 蓝紫主强调 + 四色关系语义（前置/组成/比较/应用）。
- 系统字体（PingFang SC / Microsoft YaHei），4/8px 间距基线，90rem 内容上限，焦点环、跳转链接、`prefers-reduced-motion` 均已实现。
- 响应式断点覆盖 320–1440px，无 JavaScript 路径可读（`details` 展开、原生降级）。

## 3. 优点（应保留，改造不得破坏）

1. **判断式教学法**：情境 → 三选项分档（推荐/有条件/高风险）→ 逐项反馈 → 核心原则 → 检查项 → 按需深挖。这是全站最有价值的资产。
2. **案例六 Gate**：同一业务对象连续六次评审，材料逐步形成，最终汇成完整评审档案。这是「把判断串成项目」的正确形态。
3. **内容诚实**：状态标注、待验证数字不编造、来源可复核。这是可信任的知识库的根基。
4. **工程与质量门禁**：`pnpm run ci` 覆盖格式/校验/生成物漂移/单测/构建/性能/E2E/无障碍，且有固定反例防回归。
5. **视觉统一**：设计 Token 化、语义色、间距与焦点一致，全站收敛良好。

## 4. 核心诊断：为什么目前不足以支撑「转岗 AI 产品经理」

### 4.1 【致命】定位错配：教「判断」，不教「做产品」

站点自我定义为「AI 产品判断力学习系统」（README 原文），这个定义是诚实的。但目标用户要的是「转岗 AI 产品经理」，二者之间隔着一整层 **PM 基本功**。

以关键词全量检索 `src/content`、`src/data` 验证产品经理核心技能覆盖：

| 关键词    | 命中文件数 | 关键词     | 命中文件数 |
| --------- | ---------- | ---------- | ---------- |
| PRD       | 0          | 需求分析   | 0          |
| 用户研究  | 0          | 用户访谈   | 0          |
| 商业模式  | 0          | 定价       | 1          |
| 路线图    | 0          | 项目管理   | 0          |
| 竞品      | 1          | MVP        | 0          |
| A/B 测试  | 0          | 北极星指标 | 0          |
| 职业/转岗 | 0          | 面试       | 0          |

**缺口归纳**（一名 AI PM 至少需要，而站点完全没有）：

- **发现与定义**：用户研究、需求访谈、需求分析、问题定义。
- **方案与文档**：PRD / 需求文档、验收标准、技术协作（与工程师/设计/数据如何分工）。
- **规划与排序**：优先级、路线图、MVP 切分、项目管理。
- **商业与增长**：商业模式、定价、指标设计、实验（A/B）、上线与增长。
- **职业路径**：AI PM 岗位画像、能力地图、作品集/面试。

结论：**「AI 判断力」是 AI PM 的其中一项能力，不是全部。** 站点目前把「能力项」当成了「职业入口」。

### 4.2 【高】易懂性：入门门槛过高，缺 onboarding

- **首页 = 课程目录**：`index.astro` 与 `learn/index.astro` 渲染同一个 `<LearningCatalog>`，首页没有任何「这是给谁、学什么、怎么开始」的定位说明。新用户落地即面对一堵 24 题墙。
- **三层概念未解释**：题目页有「返回三层学习中心」，但 `Level 1/2/3` 是什么、三者如何配合，入口页从未讲清。
- **术语先于解释**：Q01 即出现「大模型」，Q03 用「上下文容量」，Q08/Q10 用「Agent」，Q09 用「Prompt/RAG」，Q11 用「微调」。初学者只能靠点「按需深挖」跳转词条，学习被反复打断。
- **中英混排**：`Scenario / Make a judgment / Decision logic / Level / Gate / Domain` 等英文 eyebrow 标签，对非英语背景的初学者是额外认知负担。

### 4.3 【高】学习路径与引导不足

- 无进度记录（这是明确的产品边界：不登录、不存选择），但对自学者意味着**无法续学、无法感知完成度**。
- 目录卡片直接展示 `principle`（核心原则 = 答案），题目页「核心原则」在选择前也始终可见——**「先判断再看答案」的教学设计被自己削弱**。
- 无「新手起点」或「定位测试」：目标用户不知道该从 24 题、案例、还是词条开始。

### 4.4 【中】内容深度分布严重偏向技术域

按域核验数（80 篇 verified 的分布）：

| 域             | verified | 域           | verified |
| -------------- | -------- | ------------ | -------- |
| 提示与上下文   | 16       | 大模型与生成 | 15       |
| 机器学习       | 11       | AI 产品体验  | 10       |
| Agent 与自动化 | 7        | 检索与 RAG   | 6        |
| 评估与质量     | 5        | 工程运维     | 4        |
| 安全与治理     | 3        | AI 基础      | 2        |
| 算力与产业     | 1        | **多模态**   | **0**    |

**问题**：深度内容集中在「提示词 / 大模型 / 机器学习」等技术域；而 AI PM 最需要的「产品体验、评估质量、安全治理、工程运维」合计仅 22 篇，多模态为 0。**越靠近「产品」的域，深度内容越少。**

### 4.5 【中】案例数量与完成度不足

- 仅 2 个案例：客服知识库（`verified`）+ 每日反馈分析（`draft`）。
- README 规划的 5 个重点案例（销售助手、合同审核、内容生产、内部运营自动化等）未落地。
- 目标用户缺少「可模仿的完整项目样本」。

### 4.6 【低】视觉/体验细节

- 目录卡片信息密度过高（每卡：标题 + 问题 + 场景 + 3 事实 + 原则，× 24 卡），首屏冗长。
- 部分页面标题 2.75–3rem、题目页 hero 高度 24rem，视觉大气但信息效率可再收敛。
- 中英文标签混排（见 4.2）。

## 5. 改造目标与成功标准

**目标**：让站点从「AI 产品判断力学习库」升级为「**面向转岗者的落地型 AI 产品经理学习系统**」——既能学会判断，也能学会做产品，且对真正的初学者易懂、可续学。

**成功标准（可验证）**：

1. 一名零 AI 基础、零 PM 基础的用户，能在 10 分钟内说清「我该从哪开始、学完能做什么」。
2. 内容覆盖 AI PM 六项核心能力（判断、发现、方案、规划、商业、落地），每项都有对应学习材料与练习。
3. 24 题中的术语都有内联解释或前置词条，不再需要跳转才能读懂题意。
4. 首页与「系统课程」差异化：首页做定位与入口，课程页做目录。
5. 至少 3 个可模仿的完整案例（含 PM 交付物：PRD/指标/路线/上线计划），至少 1 个为 `verified`。
6. 全部改造通过既有 `pnpm run ci` 与目标用户 5 人任务型验收。

## 6. 完整改造计划（按优先级）

> 原则：**先补「定位与路径」，再补「PM 基本功」，最后优化「易懂与视觉」**。每项给出做什么 / 为什么 / 验收。所有内容改造复用现有 8 段正文 + 双来源 + 状态标注 + 生成管线，不破坏诚实性。

### P0 — 定位与信息架构（先让「转岗」这件事成立）

**P0-1 重建首页为「转岗 AI PM 学习入口」**

- 做什么：首页不再复用 `LearningCatalog`。改为：① Hero（一句话定位：给谁 / 学什么 / 能做什么）；②「转岗路径 / 判断题库 / 案例实战 / 知识图鉴」四个明确入口；③ 一张「Level 1→2→3 + 知识基础设施」的学习结构图；④ 一个显式的「开始学习」主行动。
- 为什么：解决「首页=课程目录」与「三层概念不清」两个最高优先级问题。
- 验收：新用户落地首页能在 10 秒内说清站点用途与起点；`/learn/` 仍为纯目录。

**P0-2 讲清三层学习结构**

- 做什么：在首页与课程页顶部增加一段「三层学习中心」说明：Level 1 = 24 道判断基础题；Level 2 = 连续案例；Level 3 = 完整项目；知识图鉴/路线/图谱是随时可查的支撑层。
- 为什么：三层是本产品的核心心智，但当前从未被解释。
- 验收：题目页「返回三层学习中心」有对应的、可读的解释页面/区块。

**P0-3 新增「转岗 AI 产品经理」综合学习路线**

- 做什么：在「阅读路线」下新增一条职业导向路线，把「AI 判断 6 阶段 + 案例实战 + PM 基本功」串成一个顺序，并标注每段产出（判断 → 需求 → PRD → 指标 → 上线）。
- 为什么：把「能力项」重新组织为「职业路径」。
- 验收：路线页可见，路线内容通过现有关系/词条门禁。

### P1 — 内容：补齐产品经理基本功（「学会 AI PM」的关键）

**P1-1 新增「AI 产品经理基本功」知识域（或子系列）**

- 做什么：按 8 段正文 + 双来源 + 状态标注，新增一批词条，覆盖：
  - 发现：用户研究、用户访谈、需求分析、问题定义；
  - 方案：PRD、验收标准、技术方案协作、AI 能力边界落地；
  - 规划：优先级（RICE/WSJF）、路线图、MVP 切分、项目管理；
  - 商业：商业模式、定价、指标设计、A/B 实验、上线与增长；
  - 职业：AI PM 能力地图、转岗路径、作品集与面试。
- 为什么：直接补齐 4.1 的致命缺口。
- 验收：`PRD / 需求分析 / 用户研究 / 商业模式 / 路线图` 等关键词在内容中可检索；每篇通过来源与状态门禁。

**P1-2 把「AI 判断」绑定「PM 落地动作」**

- 做什么：为 24 题的「检查项」之后，增加一条「如果你是 PM，下一步做什么」的落地钩子（例：Q07 错误成本 → 「写出该场景的 PRD 验收标准与错误分级」），链接到 P1-1 的对应词条。
- 为什么：让判断不再停留在结论，而是落到 PM 交付物。
- 验收：24 题均有落地钩子，且链接目标存在。

**P1-3 补重点案例并优先核验黄金项目**

- 做什么：按既有案例 Schema 与生产 Gate，依次落地销售助手、合同审核、内容生产、内部运营自动化案例；把「每日反馈分析」从 `draft` 推向 `verified`。
- 为什么：为目标用户提供 ≥3 个可模仿的完整项目样本。
- 验收：案例库 ≥3 案例、≥2 `verified`；每案通过 6 Gate + 指标 + 失败模式 + 来源门禁。

**P1-4 补产品域深度内容短板（已完成）**

- 做什么：已完成 `AI 产品体验 / 评估与质量 / 安全与治理 / 工程运维` 域的目录词条核验，并把多模态域从 0 补齐到完整核验。
- 为什么：让「越靠近产品」的域也有深度内容。
- 验收：产品相关域 verified 数量已补齐，多模态不再为 0。

### P2 — 易懂与体验（降低门槛、增强可续学）

**P2-1 术语内联解释**

- 做什么：在 24 题与案例中，为关键术语（大模型、RAG、Agent、微调、上下文、Token 等）增加内联脚注/悬停解释 + 前置词条链接，不再只靠「按需深挖」。
- 为什么：解决 4.2 的术语门槛。
- 验收：Q01–Q11 的每个术语都可原地读懂。

**P2-2 隐藏「答案」强化判断**

- 做什么：目录卡片不直接展示 `principle`，改为「你来做判断 →」钩子；题目页「核心原则」在选择前折叠、选择后揭示。
- 为什么：恢复「先判断、再看方法」的教学闭环。
- 验收：无 JavaScript 时原则仍可读（用 `details` 或渐进增强），不违反无 JS 路径要求。

**P2-3 可续学（需先取得用户授权）**

- 做什么：在**不建账号、不上传**的前提下，用 `localStorage` 记录「最近学习位置 / 已答题目」；在首页提供「继续学习」。
- 为什么：解决自学者无法续学的问题。
- 注意：这突破了现有「不保存选择/进度」的产品边界，**必须先取得用户明确授权**再实施。

**P2-4 视觉与文案收敛**

- 做什么：目录卡片降密度（只留标题 + 一句钩子）；中文为主、英文小字为辅；统一 eyebrow 文案；首页与课程页标题字号再收敛一档。
- 为什么：解决 4.6 的信息密度与中英混排。
